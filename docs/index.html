What is it

SFrontiers.jl is a Julia package for flexible estimation of stochastic frontier models. It uses simulated maximum likelihood, automatic differentiation, and GPU acceleration to deliver accurate estimation with practical runtime. The package supports three distributions for the noise term (v), eleven for the inefficiency term (u), copula-based dependence, and selected panel-data specifications, all within a unified workflow. Its estimates typically match closed-form MLE benchmarks to several decimal places.

1. Introduction

This package provides a unified framework for estimating stochastic frontier (SF) models via simulation-based likelihood evaluation and, for a limited subset of models, analytic maximum likelihood estimation (MLE). The simulation-based methods, including the Maximum Simulated Likelihood Estimation (MSLE) and Monte Carlo Integration (MCI), support a broad class of distributional and dependence specifications. For the classical Normal–half-normal, Normal–truncated-normal, and Normal–Exponential models, closed-form analytic MLE is also available.

To address the traditional drawbacks of simulation-based estimation, the package uses automatic differentiation for accurate derivatives and GPU computing for speed. Monte Carlo evidence in Wang and Cheng (2026) shows that the resulting estimators achieve bias and RMSE comparable to those of analytic maximum likelihood estimators where such benchmarks exist.

For the theoretical background of the methods, see Wang and Cheng (2026).

Key features of the package:

  • Three estimation methods: Maximum Simulated Likelihood Estimation (MSLE), Monte Carlo Integration (MCI), and Analytic Maximum Likelihood Estimation (MLE).

    • MSLE and MCI are simulation-based, using Halton base-2 sequence as the quasi Monte Carlo (QMC) draws. As shown in Wang and Cheng (2026), MSLE is a special case of MCI. The two names are retained here following conventions in the literature.

    • MLE evaluates the log-likelihood without simulation: in closed form, and for the :panel_TFE_CSW and :panel_TRE panel models by one-dimensional quadrature. No simulation draws are needed, making it fast and exact. Selected models only.

  • Distributional flexibility for cross-sectional models: For cross-sectional models (datatype=:cross_sectional in sfmodel_spec()), combinations between the following sets are supported using MSLE and MCI:

    • \(v\): Normal, Student T, and Laplace distributions.
    • \(u\): half-normal, truncated-normal, Exponential, Weibull, Lognormal, Lomax, Rayleigh, Gamma, and Erlang (orders 2, 3, 4) distributions.

    MCI supports all inefficiency distributions, and MSLE supports all except Gamma. MSLE generates its inefficiency draws through the quantile (inverse-CDF) function, and the obstacle for Gamma is not merely the lack of a closed form: the estimated shape parameter \(k\) sits inside the quantile, so a numeric inversion would have to be repeated inside every likelihood evaluation, at every optimizer iteration, with automatic differentiation flowing through it. That inversion is a slow scalar special-function computation, incompatible with the package’s AD and GPU pipelines, which is why Gamma is MCI only. Erlang also lacks a closed-form inverse CDF (for order \(m \geq 2\)), but its shape is pinned at the integer \(m\) and \(\theta\) is a pure scale, so the quantile factorizes as \(Q(p; m, \theta) = \theta \cdot q_m(p)\), where the standardized quantile \(q_m\) depends only on the fixed Halton draws and never on an estimated parameter. The package evaluates \(q_m\) with a fast Newton iteration on the closed-form Erlang CDF (elementary operations only, GPU-compatible, and exact under AD because no differentiated quantity enters the iteration), which is what makes Erlang available under MSLE. MCI avoids quantiles entirely via a change-of-variables approach. MLE is limited to half-normal, truncated-normal, and Exponential with Normal noise.

  • Distributional flexibility for panel-data Models: For panel data models, the noise (\(v\)) distribution is always fixed at the normal distribution. The package currently supports the following types of panel stochastic frontier models:

    • datatype=:panel_TFE — Wang and Ho (2010) true fixed-effect model. Supports MCI, MSLE, and MLE (half-normal/truncated-normal only for MLE). The simulation-based panel model accommodates all 11 \(u\) distributions via MCI/MSLE (Gamma is MCI only, as in the cross-sectional case).
    • datatype=:panel_TFE_CSW — Chen, Schmidt, and Wang (2014) fixed-effect model. MLE only, half-normal only.
    • datatype=:panel_TRE — True random-effect model. MLE only, half-normal or truncated-normal.

  • Copula dependence (cross-sectional only): Gaussian, Gumbel, Clayton, and 90°-rotated Clayton copula support for modeling dependence between noise \(v\) and inefficiency \(u\) for cross-sectional models, with automatic computation of the dependence parameter and Kendall’s \(\tau\). Copulas are not available for panel data models.

    • Exception: When \(v\) is Student T, the copula is not supported (the copula density requires evaluating the Student-t CDF, to which its standard implementation is not compatible with the automatic differentiation used in the package).

  • Heteroscedastic inefficiency specifications: For cross-sectional models, the parameters of the inefficiency distribution can be modeled as functions of covariates, consistent with common practice in modern SF applications. Cross-sectional models also support the scaling property model \(u_i = h(\mathbf{z}_i) \cdot u_i^*\), where \(h(\mathbf{z}_i) = \exp(\mathbf{z}_i'\boldsymbol{\delta})\) and \(u_i^*\) follows a homoscedastic base distribution. For panel data models, heterogeneity enters via the same scaling function \(h(z_{it}) = \exp(z_{it}'\delta)\).

  • Compute important statistics and quantities: For every model estimation, it automatically computes important statistics and quantities for post-estimation analysis. For instance, the inefficiency (JLMS) and efficiency (BC) index, the marginal effects of the determinants of inefficiency, the OLS log-likelihood (cross-sectional models) and the skewness of the OLS residuals.

  • Post-estimation tools: Functions for exploring fitted models, evaluating model quality through numerical summaries and plots, and using fitted models to predict frontier values, JLMS/BC indices, and marginal effects for new data.

  • CPU and GPU execution: Simulation-based methods typically require a large number of Monte Carlo draws for accuracy, making computation costly on the CPU. GPU execution substantially reduces runtime in such settings and makes applications practical.

  • Automatic differentiation (AD): The module uses AD to compute derivatives for gradient-based optimization. AD gives highly accurate derivatives of the implemented numerical objective. The implemented objective differs from the intended likelihood in known ways: the integral is approximated with a finite set of draws, parameters are kept within numerical bounds, and with Laplace noise the absolute value in the density is smoothed (see Supported Models). The improved accuracy is especially important for maintaining numerical stability in challenging optimization problems.

  • Estimation with a unified five-step procedures: Some of the steps are optional.

    • Specify the model using sfmodel_spec().
    • Choose the estimation method using sfmodel_method().
    • Initialize parameters using sfmodel_init().
    • Configure optimization using sfmodel_opt().
    • Estimate the model using sfmodel_fit().

2. Hardware and Software Requirements

2.1 Hardware

  • CPU execution. Any modern personal computer supported by Julia is sufficient for CPU-only estimation. The run time and memory of MCI and MSLE grow in proportion to the number of observations (firms, in panel models) times the number of draws per observation, n_draws, which is 4,096 by default; see Choosing the Number of Halton Draws.
  • GPU execution (optional but highly recommended for MSLE and MCI methods). Requires an NVIDIA GPU. The GPU memory a fit needs grows with the number of observations times n_draws and falls in proportion to the chunks option of sfmodel_method(), which processes the observations in groups; if VRAM is limited, raise chunks (see About GPU and chunks options).

2.2 Software

  • Julia, which is a free and open-source programming language. A recent stable release is recommended. Julia 1.10 or later is required for GPU execution via CUDA.jl. (julialang.org)
  • Optim.jl, the optimization package used by SFrontiers.jl for maximum likelihood estimation. Version 1 or above is supported; the package is developed against version 2. It must be loaded (using Optim) alongside SFrontiers in every session.
  • NVIDIA driver and CUDA.jl (optional). In addition to a physical GPU unit, GPU execution also requires a compatible NVIDIA driver installed on the machine, and CUDA.jl installed in Julia. SFrontiers works with CUDA.jl 6.4 or earlier: CUDA.jl 6.5 fails to compile the GPU sums over the dual numbers with which MCI and MSLE fits compute derivatives, so the package declares this bound, and the package manager installs CUDA.jl 6.4 when CUDA.jl and SFrontiers are in the same environment. The package also supports CPU-only execution, which does not require the driver or CUDA.jl. (cuda.juliagpu.org)

3. Installation and Dependencies

SFrontiers.jl is a registered Julia package. Install it from Julia using the built-in package manager Pkg:

using Pkg
Pkg.add("SFrontiers")

Load SFrontiers.jl and the required package for CPU-only computing:

# CPU-only usage (no CUDA needed):
using SFrontiers
using Optim

Load the packages for GPU computing:

# GPU usage:
using CUDA          # Load CUDA first
using SFrontiers    # Then load SFrontiers
using Optim

Note 1: CUDA.jl is needed only if you want GPU-accelerated estimation via sfmodel_method(method=:MCI, GPU=true) or sfmodel_method(method=:MSLE, GPU=true). MLE estimation does not use GPU.

Note 2: If you plan to use GPU features, CUDA.jl must be loaded before SFrontiers.jl. This is because SFrontiers conditionally detects CUDA at load time and registers GPU function overloads only if CUDA is already available. If CUDA is loaded after SFrontiers, GPU features will not be available and you will need to restart Julia and load them in the correct order.

Note 3: If you want to use the diagnostic plot recipes (e.g., plot(result, :efficiency)), you must also load Plots.jl by using Plots.

4. Overview and Quick Reference Example

Here we show a complete five-step estimation and post-estimation example. Some steps are optional and can be skipped; more examples latter.

using CUDA
using SFrontiers
using Optim
using CSV, DataFrames

# Load data. The csv has column names y, x1, x2, and x3 that are used as variable names.
df = CSV.read("demodata.csv", DataFrame)
y = df.y
X = hcat(ones(length(y)), df.x1, df.x2)  # Frontier variables (include constant)
Z = hcat(ones(length(y)), df.x3)          # Inefficiency determinants

# Step 1: Specify the model
myspec = sfmodel_spec(
    type = :production,        # for production frontier; alt. :cost
    depvar = y,                # dependent variable; a vector
    frontier = X,              # matrix of X vars in frontier
    zvar = Z,                  # matrix of Z vars for inefficiency
    noise = :Normal,           # dist of v
    ineff = :TruncatedNormal,  # dist of u
    hetero = [:mu, :sigma_u_sq], # heteroscedastic of u's μ & σᵤ²
)

# alternative Step 1: DSL style using DataFrame column names
df._cons = ones(nrow(df))      # create a constant column first
myspec_alt = sfmodel_spec(
    type = :production,
    @useData(df),
    @depvar(y),                # column name in df
    @frontier(_cons, x1, x2),  # column names 
    @zvar(_cons, x3),          # column names
    noise = :Normal,
    ineff = :TruncatedNormal,
    hetero = [:mu, :sigma_u_sq],
)

# Step 2: Choose the estimation method
mymeth = sfmodel_method(
    method = :MSLE,           # :MLE, :MSLE, or :MCI
    n_draws = 2^12,           # Halton draws per observation (default 2^12 = 4096)
    GPU = true,               # use GPU; default is `false` thus CPU
    chunks = 10               # observations processed in 10 groups; bounds memory (default 10)
)

# Step 3: Set initial values
myinit = sfmodel_init(
    spec = myspec,              # from sfmodel_spec()
    frontier = X \ y,           # OLS estimates
    mu = zeros(size(Z, 2)),     # μ coefficients
    ln_sigma_u_sq = zeros(size(Z, 2)),  # ln(σᵤ²) coefficients
    ln_sigma_v_sq = [0.0]       # ln(σᵥ²)
)

# Step 4: Configure optimization for Julia's Optim
myopt = sfmodel_opt(
    warmstart_solver = NelderMead(),  # first stage "warm-up" estimation
    warmstart_opt = (iterations = 200, g_abstol = 1e-5),
    main_solver = Newton(),           # 2nd stage "main" estimation
    main_opt = (iterations = 100, g_abstol = 1e-8)
)

# Step 5: Estimate the model
result = sfmodel_fit(
    spec = myspec,         # from sfmodel_spec()
    method = mymeth,       # from sfmodel_method()
    init = myinit,         # from sfmodel_init()
    optim_options = myopt, # from sfmodel_opt()
    marginal = true,       # marginal effects of Z; the default
    show_table = true      # print estimation table; the default
)

# Access results: two complementary styles

# (a) Direct field access on the result object:
println("coefficients:           ", result.coeff)
println("BC efficiency index:    ", result.bc)        # E(exp(-u)|ε), per obs
println("JLMS inefficiency idx:  ", result.jlms)      # E(u|ε), per obs
println("Marginal Effects of Z:  ", result.marginal)

# (b) StatsAPI-conformant accessor functions (work on `result`):
coeftable(result)              # formatted coefficient table (estimates, SE, z, p, CIs)
coef(result)                   # coefficient vector
vcov(result)                   # variance-covariance matrix
stderror(result)               # standard errors
confint(result; level = 0.95)  # Wald confidence intervals
loglikelihood(result)          # maximized log-likelihood
aic(result); bic(result)       # information criteria
nobs(result)                   # number of observations
residuals(result)              # composed errors (also `:u`, `:v`, `:ols` via `type=`)
fitted(result)                 # frontier fitted values x'β̂

# See Sections 6–7 (API Reference) for further diagnostics
# (efficiency_summary, residual_diagnostics, sf_skewness_test, sf_vs_ols, lrtest),
# plotting recipes, and prediction on new data.

For models with Normal noise and half-normal, truncated-normal, or Exponential inefficiency, analytic MLE is available and requires no simulation settings:

mymeth_mle = sfmodel_method(method = :MLE)  # no draws, GPU, or chunks needed
result_mle = sfmodel_fit(spec = myspec, 
                         method = mymeth_mle, 
                         init = myinit, 
                         optim_options = myopt)

5. A Detailed Empirical Example

We replicate the empirical study of Wang (2002) using the same dataset to walk through the full specification and estimation process. The model is a cross-sectional stochastic production frontier with normal noise and truncated-normal inefficiency, where both \(\mu\) and \(\sigma_u^2\) of the inefficiency distribution are parameterized by exogenous determinants.

Although this model admits a closed-form MLE (which was used by Wang 2002), we demonstrate estimation via MSLE to illustrate the simulation-based workflow. The MSLE estimates are extremely close to those of MLE in this example, with most of the estimates typically agreeing to at least 5 decimal places.

Model Setup

The specification is as follows:

\[ \begin{aligned} y_i &= x_i'\beta + \varepsilon_i, \\ \varepsilon_i &= v_i - u_i, \\ v_i &\sim N(0, \sigma_v^2), \\ u_i &\sim N^+(\mu_i, \sigma_{u,i}^2), \\ \mu_i &= z_i'\delta, \quad \sigma_{u,i}^2 = \exp(z_i'\gamma). \end{aligned} \]

Here, \(N^+(\mu, \sigma_u^2)\) denotes a truncated-normal distribution obtained by truncating \(N(\mu, \sigma_u^2)\) from below at 0. The vector \(z_i\) contains exogenous determinants of inefficiency. Wang (2002) parameterizes both \(\mu\) and \(\sigma_u^2\) by the same vector \(z_i\), while Battese and Coelli (1995) parameterize only \(\mu\).

Goals of Estimation

Our goals include:

  • Estimate model parameters \(\{\beta, \delta, \gamma, \sigma_v^2\}\).
  • Compute the JLMS inefficiency index \(E[u_i \mid \varepsilon_i]\) and the Battese–Coelli efficiency index \(E[\exp(-u_i) \mid \varepsilon_i]\) at the observation level.
  • Calculate the marginal effect of \(z_i\) on \(E(u_i)\).

myspec = sfmodel_spec(
    type   = :production,

Step 2: Choose the Estimation Method

mymeth = sfmodel_method(
    method  = :MSLE,     # or :MCI, :MLE
    n_draws = 2^13,      # number of Halton draws per observation
    GPU     = true       # set true for GPU acceleration
)
  • :MSLE uses inverse-CDF sampling; :MCI uses change-of-variables integration; :MLE uses the closed-form analytic likelihood (available for this model since it is normal–truncated-normal).
  • More draws improve accuracy at the cost of computation time. GPU acceleration (GPU = true) makes large draw counts practical.

Step 3: Set Initial Values (optional)

myinit = sfmodel_init(
    spec          = myspec,
    # frontier    = ...,          # skip to use OLS-based defaults
    mu            = zeros(4),     # 4 coefficients in μ equation
    ln_sigma_u_sq   = zeros(4),     # 4 coefficients in ln(σ²_u) equation
    ln_sigma_v_sq = [0.0]         # 1 coefficient in ln(σ²_v)
)
  • The order of keyword arguments does not matter.
  • If sfmodel_init() is not called, the package uses OLS-based defaults for the frontier and 0.1 for every other parameter, \(\mu\) included. (The true-fixed-effects panel model overrides a few components; see Section 6.3.)
  • Initial values for variance parameters are on the log scale (e.g., ln_sigma_v_sq = [0.0] means the initial \(\sigma_v^2 = \exp(0) = 1.0\)).

Step 4: Configure the Optimizer (optional)

An effective strategy for challenging problems is a two-stage approach: a gradient-free solver first to find a good neighborhood, then a gradient-based solver for precise convergence.

myopt = sfmodel_opt(
    warmstart_solver = NelderMead(),
    warmstart_opt    = (iterations = 200, g_abstol = 1e-5),
    main_solver      = Newton(),
    main_opt         = (iterations = 100, g_abstol = 1e-8)
)
  • NelderMead() (gradient-free) in the warm-start stage is robust to poor starting values.
  • Newton() (second-order, gradient-based) in the main stage converges quickly and precisely.
  • If sfmodel_opt() is not called, every method uses the same two-stage default: NelderMead() for 200 iterations (g_abstol = 1e-3), then Newton() for 200 iterations (g_abstol = 1e-7).

Hypothesis Testing

sf_vs_ols tests the frontier against OLS (\(H_0\): no inefficiency, \(u \equiv 0\)). The null distribution of its likelihood-ratio statistic is established for the cross-sectional model with normal noise, no copula and homoscedastic half-normal inefficiency, where it is \(\tfrac{1}{2}\chi^2(0) + \tfrac{1}{2}\chi^2(1)\) (Lee 1993), and sf_vs_ols accepts only fits of that model. For this section’s model, whose truncated-normal \(\mu\) and \(\sigma_u^2\) depend on \(z\), sf_vs_ols(result) raises an error: under \(H_0\) the coefficients of \(\mu\) and the slope coefficients of \(\sigma_u^2\) are not identified, and counting them does not determine the null distribution of the statistic. To show the test, we fit the homoscedastic normal–half-normal model to the rice data:

spec_hn = sfmodel_spec(
    type   = :production,
    @useData(df),
    @depvar(yvar),
    @frontier(_cons, Lland, PIland, Llabor, Lbull, Lcost, yr),
    noise  = :Normal,
    ineff  = :HalfNormal,
)
result_hn = sfmodel_fit(spec = spec_hn, method = sfmodel_method(method = :MLE),
                        optim_options = myopt, show_table = false)
julia> sf_vs_ols(result_hn)
Likelihood-ratio test (mixed χ̄² reference distribution)
  LR statistic   : 23.207785
  degrees of freedom: 1
  p-value        : 1.0e-6
  log-lik (R, U) : (-104.9699, -93.366)
  critical values: 10% = 1.6424, 5% = 2.7055, 2.5% = 3.8415, 1% = 5.4119

Prediction on New Data

The fitted object can be applied to new observations through predict(result; frontier, zvar, depvar, what). See ‘Prediction on New Data’ in Section 7.7 for the full reference (signature, the what-keyword table, and supported model classes).

Given any new observations \((X_{\text{new}}, Z_{\text{new}}, y_{\text{new}})\), predict() reuses the estimated coefficients — no refitting — to return the same family of quantities available at training time: the frontier fit \(x_i'\hat\beta\), composed residuals, response-scale fit, the JLMS inefficiency index \(E(u_i\mid\hat\varepsilon_i)\), the Battese–Coelli efficiency index \(E(e^{-u_i}\mid\hat\varepsilon_i)\), and the observation-level marginal effects \(\partial E(u_i)/\partial \mathbf{z}_i\). The what keyword selects the target.

This interface supports several post-estimation tasks:

  • Out-of-sample prediction and evaluation. Score firms outside the estimation sample, such as in train/test splits, cross-validation, or newly collected data, against the fitted frontier and obtain out-of-sample JLMS/BC scores.

  • Counterfactual analysis. Change inefficiency determinants \(Z\) and recompute \(E(u\mid\varepsilon)\) or \(E(e^{-u}\mid\varepsilon)\) to see how predicted (in)efficiency changes.

  • Policy evaluation. Apply the fitted model to post-intervention data or a simulated \(Z\) distribution to project changes in mean efficiency without refitting.

  • Forecasting. Fit on periods \(1,\dots,T-1\) and predict frontier output and efficiency for period \(T\).

  • Sensitivity and marginal analysis. Use what = :marginal over a grid of \(Z\) values to trace how marginal effects vary across the covariate space.

  • Scoring new entrants. Apply an existing fitted model to newly collected firms without re-estimating the model.

The exact signature, data-requirement table, and currently-supported model classes are documented in Section 7.7 ‘Prediction on New Data’.

6.1 sfmodel_spec()

The sfmodel_spec() function creates a model specification object that encapsulates all data, distributional assumptions, and metadata required for estimation. It is independent of the choice of estimation method.

A specification object is self-contained, and sfmodel_fit() estimates the specification it is handed. You may build as many specifications as you like, in any order, and fit them in any order afterwards; building a second one does not disturb the first. The same holds for the objects returned by sfmodel_method(), sfmodel_init() and sfmodel_opt(): each fit uses the objects passed to that call and nothing left over from an earlier one.

Example: Scaling Property Model

The scaling property model uses hetero = :scaling. In this specification, zvar provides the environmental variables \(\mathbf{z}_i\) for the scaling function \(h(\mathbf{z}_i) = \exp(\mathbf{z}_i'\boldsymbol{\delta})\), and the inefficiency distribution parameters remain scalar (homoscedastic). The zvar matrix must not contain a constant column (for identification; see Section 9.4).

# Scaling property model (using keyword form as an example)
# Z_nocons must NOT contain a constant column

Z_nocons = hcat(df.age, df.school, df.yr)

spec = sfmodel_spec(
    type = :production,
    depvar = y,
    frontier = X,           # include constant as usual
    zvar = Z_nocons,        # environmental variables (no constant!)
    noise = :Normal,
    ineff = :HalfNormal,
    hetero = :scaling,      # scaling property model
)

# Scaling + copula (allowed)
spec = sfmodel_spec(
    type = :production,
    depvar = y,
    frontier = X,
    zvar = Z_nocons,
    noise = :Normal,
    ineff = :Exponential,
    hetero = :scaling,
    copula = :Clayton,
)

Notes on scaling property model:

  • hetero = :scaling cannot be combined with heteroscedastic parameters (:mu, :sigma_u_sq, etc.), since the heteroscedasticy is specified through the scaling function, not individual parameters.
  • zvar is required and must not contain a constant column in the case of hetero = :scaling.
  • All inefficiency distributions are supported. :Gamma requires method = :MCI.
  • Copula models are supported.
  • Both :MSLE and :MCI estimation methods are supported (ineff = :Gamma is MCI only).

About GPU and chunks options

The chunks option is effective for simulation-based estimators (:MSLE and :MCI); no use for :MLE. It works for both CPU and GPU computation and is particularly essential for GPU computing (GPU=true).

:MSLE :MCI :MLE
CPU ✓ ✓ —
GPU ✓✓ ✓✓ —

Simulation-based estimation (MSLE and MCI) evaluates the likelihood contribution of every observation (every firm, in panel models) at each of its D = n_draws draws. The draws are generated once per fit, as one N × D matrix in the data’s element type (one shared row of D draws when multiRand = false), and the fit and its result keep that one matrix (see the model field in the Return Value of sfmodel_fit()). The likelihood, its derivatives, the efficiency indices after the fit and predict() process the observations in chunks groups of about N/chunks observations each and read each group’s rows of the matrix without copying the matrix, so their memory falls in proportion to chunks, on the CPU and on the GPU, for cross-sectional and panel models alike. With chunks = 1 all observations are processed at once.

How much memory. The draw matrix itself is small: 8 bytes per draw in Float64 and 4 in Float32. What takes memory is the work arrays computed from it for one group. Under the default Newton() main solver, and in the final Hessian that every fit computes for its standard errors (Laplace-noise fits use the outer product of gradients instead), each element of these arrays is a nested automatic-differentiation number of 8(C + 1)² bytes, whatever the data’s element type, where C = q for a model with q ≤ 12 parameters (for q > 12, C = ⌈q/⌈q/12⌉⌉, and the Hessian is formed in ⌈q/C⌉² passes of this size). One Hessian pass therefore holds about a × ⌈N/chunks⌉ × D × 8(C + 1)² bytes, where a, the number of work arrays, is 3 for MCI and 2 for MSLE in cross-sectional models (6 and 4 with a copula) and 2 for MCI and 1 for MSLE in panel models. When N is not a multiple of ⌈N/chunks⌉, the shorter last group adds one more array of its own size. For example, a cross-sectional MCI fit with N = 5,000 observations, q = 8 parameters and D = 8,192 holds about 8.0 GB at chunks = 10 and 2.0 GB at chunks = 40; with a Gaussian copula, which adds the parameter ρ, about 20 GB at chunks = 10 and 4.9 GB at chunks = 40; a panel MCI fit with 1,000 firms, 8 parameters and the same D holds about 1.1 GB at chunks = 10 (a panel MSLE fit about 0.5 GB). Each additional chunk adds a fixed cost to every likelihood evaluation, which is noticeable on the GPU (more kernel launches), so raise chunks only as far as memory requires.

Before the optimizer starts, a GPU fit compares this estimate with the free GPU memory and prints a warning that names chunks and n_draws when the estimate is larger. CPU fits make no such check, because free-memory figures are unreliable when the operating system pages memory to disk; if a CPU fit runs out of memory, raise chunks or lower n_draws (see Choosing the Number of Halton Draws). On Windows, Task Manager shows the memory in use.

6.3 sfmodel_init()

The sfmodel_init() function creates the vector of initial values for the optimizer. It returns a Vector{Float64} for every model and every estimation method, and the same vector is accepted by sfmodel_fit() under method = :MCI, :MSLE and :MLE alike. Where two backends order a block of parameters differently, sfmodel_fit() converts at the fit boundary, so the order documented for the model is the only order you need to know. sfmodel_init() supports two usage modes: full vector mode and component mode.

Calling sfmodel_init() at all is optional. If you skip it, sfmodel_fit() uses the same defaults described below.

Syntax

sfmodel_init() — set initial values for optimization.

Arguments

Every component argument is optional. A component you do not supply takes exactly the value the fit would have used had you not called sfmodel_init() at all: the OLS estimate for the frontier coefficients, and 0.1 for every other parameter, with the true-fixed-effects panel model (:panel_TFE) additionally starting \(\mu\) at 0.0 and, for Lomax, \(\ln\lambda\) at -1.0 and \(\ln\alpha\) at 0.5. (:panel_TRE and :panel_TFE_CSW take the flat 0.1, \(\mu\) included.) So omitting one component and omitting the whole call agree component by component.

A component that is not part of the model you specified is refused by name rather than silently dropped.

frontier Vector/Tuple Initial values for the frontier coefficients (\(K\) elements). Default: OLS. No
scaling Vector/Tuple Initial values for the scaling function coefficients\(\boldsymbol{\delta}\) (\(L\) elements, one per column of zvar). Used when hetero = :scaling. hscale is accepted as a synonym. No
mu Vector/Tuple Initial values for\(\mu\) (used by TruncatedNormal and Lognormal inefficiency specifications). No
ln_sigma_u_sq Vector/Tuple Initial values for\(\ln(\sigma_u^2)\) (used by TruncatedNormal, HalfNormal, Lognormal, and Rayleigh inefficiency specifications). No

Which components a model has depends on its distributions, so the arguments that apply differ by model. In particular, :panel_TFE_CSW and :panel_TRE have no scaling function and therefore accept neither scaling nor hscale; :panel_TFE_CSW is half-normal, so it has no mu; and sigma_a_sq exists only for :panel_TRE. Return Value

Returns a Vector{Float64} containing the initial parameter values in the correct order for optimization, for every datatype and every estimation method.

Mode 1: Full Vector Mode

Provide the complete parameter vector directly via the init keyword. The values must follow the model’s parameter order, which is the order given in Section 8 and is the same order result.coeff comes back in. The length is checked. This mode is generally not recommended for first-time use, since you need to know the parameter ordering. It is most useful when recycling estimates from a previous round of estimation (e.g., using a converged coefficient vector as a warm start for a re-specification).

myinit = sfmodel_init(
    spec = myspec,
    init = [0.5, 0.3, 0.2, 0.1, 0.1, 0.1, 0.0, 0.0]
)

Mode 2: Component Mode

Specify initial values by parameter group. Any group you leave out takes its default. The ordering of the keyword arguments is irrelevant; the program maps each block to the correct position in the coefficient vector automatically.

# Normal + truncated-normal with hetero = [:mu]
myinit = sfmodel_init(
    spec = myspec,
    frontier = [0.5, 0.3, 0.2],     # frontier coefficients
    mu = [0.1, 0.1, 0.1],           # mu of truncated normal
    ln_sigma_u_sq = [0.0],            # log(sigma_u^2) of truncated normal
    ln_sigma_v_sq = [0.0]           # log(sigma_v^2) of normal
)

# alternatively,
myinit2 = sfmodel_init(
    spec = myspec,
    frontier = X \ y,               # OLS coefficients
    mu = 0.1*ones(size(Z, 2)),      # mu of truncated normal
    ln_sigma_u_sq = [0.0],            # log(sigma_u^2) of truncated normal
    ln_sigma_v_sq = (0.0)           # log(sigma_v^2) of normal
)

# supply only what you want to move; the rest take their defaults
myinit3 = sfmodel_init(spec = myspec, ln_sigma_v_sq = -2.3)

Scaling Property Initial Values

When hetero = :scaling, provide the scaling keyword with initial values for the \(\boldsymbol{\delta}\) coefficients (one per column of zvar). All inefficiency distribution parameters are scalar:

# Normal + half-normal with scaling property
myinit = sfmodel_init(
    spec = myspec,
    frontier = X \ y,                   # OLS estimates
    scaling = zeros(size(Z_nocons, 2)), # δ coefficients (one per z-variable)
    ln_sigma_u_sq = [0.0],               # scalar base parameter
    ln_sigma_v_sq = [0.0]              # noise variance
)

Panel Initial Values

Panel models take the same keywords as cross-sectional models, minus the ones their distributions do not have, and all their inefficiency distribution parameters are scalar (not heteroscedastic). Two differences are worth stating explicitly. datatype = :panel_TFE does not accept message. And :panel_TFE_CSW and :panel_TRE have no scaling function, so neither accepts scaling or hscale; :panel_TRE takes sigma_a_sq for the random-effect variance, which no other model has.

# Panel TFE: Normal + half-normal
myinit = sfmodel_init(
    spec = myspec,                # assume spec with datatype=:panel_TFE
    frontier = X \ y,             # OLS on the demeaned data is the default; supply it to override
    scaling = [0.1, 0.1],        # scaling function coefficients
    ln_sigma_u_sq = 0.1,           # scalar
    ln_sigma_v_sq = 0.1          # scalar
)

# Panel TRE: Normal + half-normal. Parameter order is
# [frontier, sigma_a_sq, ln_sigma_u_sq, ln_sigma_v_sq]; with a truncated normal,
# mu comes between the frontier block and sigma_a_sq.
myinit_tre = sfmodel_init(
    spec = myspec_tre,            # assume spec with datatype=:panel_TRE
    frontier = X \ y,
    sigma_a_sq = 0.1,            # random-effect variance (log scale)
    ln_sigma_u_sq = 0.1,
    ln_sigma_v_sq = 0.1
)

Note: In panel models, all inefficiency distribution parameters are scalar (not heteroscedastic). frontier defaults to OLS — on the within-demeaned data for :panel_TFE and :panel_TFE_CSW, on the raw data for :panel_TRE — and every other parameter defaults to 0.1, apart from — in :panel_TFE only — \(\mu\), which starts at 0.0, and the two Lomax parameters described above. In :panel_TRE, \(\mu\) takes the flat 0.1 like every other non-frontier parameter.

Input Format Flexibility

All parameter arguments accept scalars, vectors, row vectors, or tuples. Tuples are the one exception: the :panel_TFE builder does not accept them.

frontier = [0.5 0.3 0.2]      # Row vector (1x3 matrix)
frontier = (0.5, 0.3, 0.2)    # Tuple — not accepted by datatype = :panel_TFE

ln_sigma_v_sq = 0.1           # a bare scalar is fine for a one-element block

6.4 sfmodel_opt()

The sfmodel_opt() function specifies the optimization options. Solvers and options are passed directly to Julia’s Optim.jl interface, so any solver and any Optim.Options keyword are permissible. All three estimation methods (MCI, MSLE, and MLE) use the same optimizer interface, so no method argument is needed, and every keyword takes effect under every method, including :MLE.

The function supports a two-stage approach where the first-stage result is used as initial values for the second-stage optimization. A practical usage is to use a derivative-free solver (e.g., NelderMead()) in the first stage (warmstart) to quickly and robustly zoom in on a good neighborhood of the optimum, and use a gradient-based solver (e.g., Newton()) in the second stage (main) to achieve precise convergence. This is often very useful for highly nonlinear models where gradient-based solvers alone may fail from poor starting values. An one-stage estimation is possible by omiiting the first stage (warmstart) estimation.

Syntax

main_solver Solver Main optimizer, e.g.,Newton(), BFGS() Yes

    warmstart_solver = NelderMead(),
    warmstart_opt = (iterations = 100, g_abstol = 1e-4),
    main_solver = Newton(),
    main_opt = (iterations = 200, g_abstol = 1e-8)
)

Example: Skip Warmstart

    main_solver = Newton(),
    main_opt = (iterations = 200, g_abstol = 1e-8)
)

Notes

  • If warmstart_solver is omitted, the warmstart stage is skipped.

  • If warmstart_solver is provided without warmstart_opt, default options are used: (iterations = 100, g_abstol = 1e-3).

  • The converse is an error. warmstart_opt without a warmstart_solver is refused, because there is no warmstart stage to configure. This holds for sfmodel_opt() and sfmodel_panel_opt() alike.

  • warmstart_opt = (iterations = 0,) skips the warmstart stage, under every method.

  • If sfmodel_fit() is called without optim_options, every method uses NelderMead() for 200 iterations (g_abstol = 1e-3) as the warmstart, then Newton() for 200 iterations (g_abstol = 1e-7).

  • With noise = :Laplace, a fit whose main stage stops without convergence is continued with BFGS() from the main stage’s endpoint, with the same options (main_opt, its iteration limit included), and the fit reports the convergence of this finish. There is no finish when the main solver is BFGS() or LBFGS(), or when main_opt allows no iterations. With the default optimizer settings, whether omitted or written out, the Newton stage of a Laplace-noise fit runs at most 30 iterations before the finish, which then has the default budget of 200 iterations; pass other main settings in optim_options to choose other budgets. See Supported Models, Laplace noise.

  • The main solver may be gradient-free (NelderMead(), ParticleSwarm(), SimulatedAnnealing()). Optim reports no gradient for these solvers, so SFrontiers computes the gradient at the estimate with ForwardDiff for gradient_norm and the gradient check of redflag. Optim never reports convergence for ParticleSwarm() and SimulatedAnnealing(), which run to the iteration limit, so as the main solver they always give converged = false and a redflag of at least 1, even at the optimum; use them in the warmstart, followed by a gradient-based main solver.

Common Pitfall: Trailing Comma for Single-Element Options

When specifying options with only one element, you must include a trailing comma to create a NamedTuple:

# CORRECT - trailing comma creates a NamedTuple
main_opt = (iterations = 200,)

# WRONG - without comma, this is just the integer 200, not a NamedTuple
main_opt = (iterations = 200)

For two or more elements, the trailing comma is not needed:

# Both work fine
main_opt = (iterations = 200, g_abstol = 1e-8)
main_opt = (iterations = 200, g_abstol = 1e-8,)  # trailing comma optional

If you forget the trailing comma, the function will display an error message:

ERROR: Invalid `main_opt`: expected a NamedTuple, got Int64.
Hint: For single-element options, use a trailing comma:
`main_opt = (iterations = 200,)` not `main_opt = (iterations = 200)`.

Convergence Warnings

Optim.jl declares convergence as soon as any of its stopping criteria is met — a small gradient norm (g_abstol), a small change in the log-likelihood (f_abstol), or a small change in the parameter vector (x_abstol). Because of this, result.converged = true does not by itself guarantee that the gradient at the reported optimum is small: the optimizer may have stopped because the objective or the parameters stopped moving, while the gradient remained sizeable.

SFrontiers.jl therefore returns an additional warning flag, redflag, that re-examines the quality of the result after Optim returns. It takes one of three values (the highest applicable value is reported, except that a boundary solution is always 1), and a result that converged reports as converged can still be flagged:

  • redflag = 0: no issues detected.
  • redflag = 1: a convergence-quality problem or a boundary solution:
    • the gradient norm exceeds 0.1 (or is NaN). This is the largest absolute element of the log-likelihood gradient at coeff; with a gradient-free main solver (NelderMead(), ParticleSwarm(), SimulatedAnnealing()) SFrontiers computes it there with ForwardDiff;
    • Optim did not report convergence (converged = false). This includes a run stopped by the iteration limit; a fit that converges on exactly its last allowed iteration is not flagged. Optim never reports convergence for ParticleSwarm() and SimulatedAnnealing(), which run to the iteration limit;
    • the line search failed, even if Optim reports convergence (it can, when its convergence test was met on the iteration before);
    • the Hessian cannot be inverted reliably: inv fails, or its reciprocal condition number (1-norm) is below machine epsilon, about 2.2e-16. All standard errors are then NaN. Besides collinearity or a flat likelihood, a value that small can come from variables measured on very different scales; see Handling Convergence Issues;
    • the Hessian is not positive definite (the test is a Cholesky factorization of the Hessian of the negative log-likelihood): the estimate is not a strict local maximum of the log-likelihood but a saddle point, or a point on a ridge along which the likelihood does not fall. The test is strict: an eigenvalue that is negative only by rounding fails it too. The standard errors are kept as computed, but they are not reliable. When a diagonal element of the variance–covariance matrix is also non-positive, the fit reads 2 instead (below);
    • a parameter is at or beyond the numerical bound SFrontiers applies to it, within a relative tolerance of 10⁻⁶: a variance or scale parameter, a shape parameter (Weibull k, gamma k, Lomax α) or the dependence parameter of the Clayton, Clayton 90° and Gumbel copulas (the bounds are listed in Parameter Bounds). For a heteroscedastic parameter, one observation at or beyond the bound is enough. Such a fit is a boundary solution. The message names each parameter at a bound, and result.bound_check records them. A homoscedastic parameter beyond a bound that its likelihood applies makes the Hessian singular, so all standard errors are NaN, and its coefficient is reported at the bound; otherwise the standard errors are kept as computed.
  • redflag = 2: the variance–covariance matrix has non-positive diagonal elements, so the affected standard errors are reported as NaN.

The flag is an Int under every method, including :MLE, and it does not depend on show_table. The same rule applies under every method.

result.hessian_flag holds the value of the Hessian rules alone (0, 1 or 2), before a boundary solution sets redflag to 1, and result.bound_check lists the parameters at a bound (see Parameter Bounds).

Beyond the bound, the simulation methods clamp the parameter, so their likelihood is flat in it there (for a homoscedastic parameter their Hessian then cannot be inverted). :MLE has no clamp, except inside the panel_TFE_CSW and panel_TRE likelihoods (see Parameter Bounds), but it applies the same bounds to σᵤ and σᵥ, so a boundary solution gets the same flag under every method. Away from a clean optimum, though (a fit that did not converge, or a degenerate point), the analytic and the simulated likelihoods and Hessians really do differ, so the same data and starting values can give, for example, 2 under :MLE and 1 under :MSLE. Compare redflag > 0, not the exact value, across methods.

Shape parameters and the dependence parameters of the Clayton, Clayton 90° and Gumbel copulas fall under the same boundary rule as variance and scale parameters (above). A homoscedastic coefficient that ends beyond its bound is reported at the bound, where the likelihood was evaluated, and the log-likelihood and the other estimates do not change (see Parameter Bounds).

Laplace noise. When the main stage of a Laplace-noise fit stops without convergence, SFrontiers continues it with BFGS from that point (see Supported Models). converged, iter_limit_reached, gradient_norm, the log-likelihood and the convergence part of redflag then refer to the finish, so a fit that genuinely fails still shows as unconverged. For these fits the Hessian part of redflag applies the same rules to the outer product of gradients.

With a main solver that does not compute second derivatives itself, such as BFGS(), LBFGS(), ConjugateGradient(), GradientDescent(), NelderMead() or ParticleSwarm(), an error while the Hessian is computed at the estimate does not end the fit. Such an error (for example a DomainError, or a MethodError that only the second derivatives raise, which ForwardDiff computes with nested dual numbers) stopped sfmodel_fit in versions before 2.0.0, under every method, and the estimate was lost. The fit returns its coefficients, log-likelihood, jlms, bc and marginal effects with redflag = 1, an all-NaN Hessian and variance–covariance matrix and all standard errors NaN, and it prints a message that gives the error, whatever verbose is. Newton(), the default main solver, and NewtonTrustRegion() compute the Hessian themselves, at the start and at every point they accept, the estimate included, so with them such an error still ends the fit, inside Optim, unless it does not occur again at the same point or the fit stopped after a failed line search under Optim 2.0, which stops at a point where Optim has not computed the Hessian. KrylovTrustRegion() computes products of the Hessian with a vector at each point from which it tries a step, the start included, but not at a point it has just accepted, which is where a fit that converges stops: with it, an error that occurs wherever second derivatives are computed (such as the MethodError above) still ends the fit inside Optim, at the first iteration, while one that occurs only at such an estimate does not, as with BFGS(). An error while SFrontiers evaluates the log-likelihood or its gradient again at the estimate, which it does after a failed line search, after a stop on an increase of the objective, and for a gradient-free main solver, does not end the fit either: gradient_norm is then NaN, so redflag = 1, and loglikelihood is the log-likelihood at the estimate when that could be evaluated, else the value Optim reports. After a failed line search under Optim 2.0 that value is the log-likelihood of the previous iterate, not of the estimate; as the line search has normally evaluated the log-likelihood at the estimate already (or at a point that differs from it only in the last bits), this case needs an error that did not occur in that evaluation. Ctrl-C (InterruptException), Julia’s OutOfMemoryError and StackOverflowError, and CUDA’s out-of-GPU-memory error still end the fit. In the :MLE bootstrap of marginal effects (Bootstrap standard errors), an error while a resample’s marginal effects are computed makes it a failed resample, drawn again and counted as a kind of its own (in versions before 2.0.0 it ended the bootstrap, and the replicates already done were lost). The same holds for an error while a resample’s Hessian is computed, when the resample’s optimizer has not already computed second derivatives at its estimate (see above); where it has, as with Newton(), an error that recurs there arises inside the optimizer and is a failed resample counted as an error of the optimizer.

Treat any redflag > 0 as a signal to inspect gradient_norm and re-run with different initial values, more iterations, or a different solver (see Handling Convergence Issues).

Integration check. converged and redflag concern the optimizer: whether it stopped, and whether the point where it stopped is a regular maximum of the simulated log-likelihood. Neither says how close the simulated log-likelihood is to the exact one. For that, sfmodel_fit(..., integration_check = true) (or sfmodel_panel_fit(..., integration_check = true)) adds one check to an MCI or MSLE fit, cross-sectional or panel_TFE. It runs once, at the estimate θ̂ and after the standard errors, and does not re-estimate:

  1. It evaluates the simulated log-likelihood at θ̂ again with 4S draws, S being the fit’s n_draws, and reports the change Δ = ℓ_4S − ℓ_S (also per observation). The 4S draws are those that a fit with n_draws = 4S and the same other settings would use, so a refit with n_draws = 4S reproduces them; with shared draws (multiRand = false) they contain the fit’s S draws.
  2. It computes the one-step shift −V(g_4S − g_S), where g_S and g_4S are the gradients of the negative simulated log-likelihood at θ̂ with S and 4S draws and V is the variance matrix behind the reported standard errors. Divided by the standard errors, the shift estimates how far re-estimating with 4S draws would move each coefficient; the check reports the largest absolute value and its coefficient.

Each part reads OK, CAUTION or FAIL, and the check reports the worse of the two: the log-likelihood part at |Δ| of 0.1 and 1 (sample totals, in nats), the shift part at 0.1 and 0.5 standard errors. The thresholds are heuristics. An error δ in a log-likelihood moves a likelihood-ratio statistic by 2δ, and |Δ| understates the error with S draws by a factor between about 4/3 and 2, so |Δ| = 1 corresponds to a change of about 2.7 to 4 in an LR statistic, the size of the 5% critical value of χ²(1), 3.84. A bias of b standard errors gives a nominal 95% confidence interval a coverage of Φ(1.96 − b) − Φ(−1.96 − b): 0.949 at b = 0.1 and 0.921 at b = 0.5. Change the thresholds with a NamedTuple, for example integration_check = (ll_caution = 0.2, ll_fail = 2.0); keys not given keep their defaults. In simulated samples of 500 observations at the true parameters, the log-likelihood part read FAIL in 457 of the 482 samples whose simulated log-likelihood at 8,192 draws was more than 1 nat off under MCI with the default rule (CAUTION in the other 25) and in all 291 such samples under MSLE, and OK in all 926 (MCI) and all 637 (MSLE) samples within 0.1 nat.

When the variance matrix is not usable (redflag says why: the Hessian, or for Laplace noise the outer product of gradients, could not be computed or inverted or is not positive definite, or a variance is not positive), or when the log-likelihood or its gradient with 4S draws is not finite, the shift is not computed, and the verdict comes from the log-likelihood part alone, marked “log-likelihood only”. The check is not available for user-supplied draws (the package cannot make four times as many of them), for a recycled Halton sequence (the recycling option, or the deprecated distinct_Halton_length) shorter than 4S points, or when the log-likelihood at θ̂ is not finite; it then reports “not available” with the reason, as it does when the 4S evaluation runs out of memory. When a recycled sequence is shorter than N × 4S points, the 4S draws reuse points of the fit’s pool and the check is weaker. The check measures how much the simulated log-likelihood moves when the draws are quadrupled; an error that does not change with the number of draws stays invisible to it.

The result is stored in result.integration_check, a NamedTuple with status (:OK, :CAUTION, :FAIL, :not_available or :error), reason, n_draws, n_draws_check, loglik, loglik_check, delta_loglik, delta_loglik_per_obs, ll_verdict, shift_available, shift_note, shift, shift_se, max_shift_se, max_shift_param, max_shift_estimate, max_shift_onestep (the largest shift in standard errors, its parameter, that parameter’s estimate and its value after the shift), shift_verdict, thresholds and seconds. It is nothing when the option is off, and :MLE, which ignores the option, has no such field. With show_table = true one line of the form Integration check: CAUTION (log-likelihood change from 4096 to 16384 draws: 0.3126; largest shift: 0.12 SE, x1 from -0.0064 to -0.0089) appears in the table header after “Converged:”; without a usable variance matrix it reads Integration check: CAUTION, log-likelihood only (...). The check changes no estimate, standard error, converged or redflag.

On CAUTION or FAIL, increase n_draws and refit; for MCI also try transformation = :logistic_2_rule, or method = :MSLE where the model has it; where the model has a closed form, compare with method = :MLE. For a likelihood-ratio test between two simulated fits, run the check on both: each Δ indicates the size of that fit’s simulation error, and the LR statistic moves by twice the difference of the two errors.

Cost: one evaluation and one gradient of the log-likelihood with 4S draws and one gradient with S draws, about 3% of the time of a default MCI or MSLE fit; for example 0.65 s against 21 s for a truncated-normal MCI fit with 500 observations on one CPU core. The 4S draws are generated once, kept as one block of N × 4S values (firms instead of observations in panel_TFE models; 8 bytes per value with Float64 data and 4 with Float32, so 0.66 GB at N = 5,000 with the default 4,096 draws in Float64) and released after the check. The evaluations run over 4 × chunks chunks, so each chunk needs the memory of one gradient evaluation of the fit, and chunks bounds it as it bounds the fit.

Running fits on threads

method = :MLE uses an analytic backend that keeps the model it works on in module-level variables. sfmodel_spec() writes them for every model that :MLE can fit (Normal noise and no copula, with half-normal or truncated-normal inefficiency, or exponential inefficiency on cross-sectional data), whatever method the fit then uses; :MLE fits, MLE_Backend.sfmodel_boot_marginal and, for :panel_TFE_CSW and :panel_TRE, sfmodel_init() read and write them as well. Run on several threads at the same time, these calls can fail or mix up models. In five runs of a test in which two threads each built a specification and ran an :MLE fit 200 times, each thread with its own model and data, 4 to 76 of the 400 fits stopped with an error and 1 to 23 returned estimates that differ from the same fit run alone; with one shared lock, all 400 fits were identical to it in every run. So when you use threads, make these calls one at a time, for example inside lock(l) do ... end with one l = ReentrantLock() shared by all threads. :MCI and :MSLE fits do not use this state and can run side by side once their specifications are built.

6.6 sfmodel_MixTable() and sfmodel_ChiSquareTable()

These two utilities print critical values used for manual likelihood-ratio (LR) testing. Use sfmodel_MixTable when the LR test places a parameter on the boundary of the parameter space, for example \(H_0: \sigma_u^2 = 0\) in the homoscedastic normal–half-normal model, where \(\sigma_u^2\) is the only restricted parameter and the reference distribution is the mixed \(\bar{\chi}^2\) of Kodde and Palm (1986) with one degree of freedom, \(\tfrac{1}{2}\chi^2(0) + \tfrac{1}{2}\chi^2(1)\) (Lee 1993). Use sfmodel_ChiSquareTable for standard interior LR tests (e.g., \(H_0: \beta_2 = \beta_3 = 0\)), where the usual \(\chi^2\) reference applies.

Syntax

sfmodel_MixTable()             # Full table (dof 1 to 40)
sfmodel_MixTable(k)            # Row of critical values for k degrees of freedom

sfmodel_ChiSquareTable(k)      # Row of critical values for k degrees of freedom

Arguments

Argument Type Description Required
dof Int Degrees of freedom. For sfmodel_MixTable, must be between 1 and 40. Omit dof in sfmodel_MixTable to print the full table. No

Return Value

A \(1 \times 5\) row (or, for sfmodel_MixTable() with no argument, a \(40 \times 5\) matrix) whose first column is the degrees of freedom and whose remaining four columns are the critical values at the significance levels 0.10, 0.05, 0.025, and 0.01. The value is returned as well as printed. The mixed table is reproduced from Table 1 of Kodde and Palm (1986, Econometrica).

The LR statistic to compare against the returned critical values is \(-2(\ln L_R - \ln L_U)\). For sfmodel_MixTable, the reference distribution is a 50:50 mixture of \(\chi^2(p-1)\) and \(\chi^2(p)\), where \(p\) is the number of restrictions and one of them places a parameter on the boundary of the parameter space. This reference applies when every other parameter is identified under \(H_0\) (Self and Liang 1987). It does not apply when parameters vanish from the likelihood under \(H_0\), as the truncated-normal location \(\mu\) and the heteroscedasticity coefficients do when \(\sigma_u^2 = 0\): counting such parameters does not determine the null distribution. For sfmodel_ChiSquareTable, it is the standard \(\chi^2(p)\).

Example: Testing for Inefficiency

# Unrestricted model: the homoscedastic normal-half-normal frontier of
# Section 5 (spec_hn); H0: sigma_u^2 = 0 restricts sigma_u^2 only, and
# no other parameter vanishes from the likelihood under H0
result_sf = sfmodel_fit(spec = spec_hn, method = sfmodel_method(method = :MLE))

# Restricted model (OLS, no inefficiency): its log-likelihood is stored in the fit
ll_ols = result_sf.OLS_loglikelihood
ll_sf  = result_sf.loglikelihood

# Compute LR statistic
LR = -2 * (ll_ols - ll_sf)

Bootstrap standard errors (method = :MLE)

For a fit with method = :MLE, SFrontiers.MLE_Backend.sfmodel_boot_marginal(result = result, R = 250, seed = 123) bootstraps the standard errors and bias-corrected confidence intervals of the mean marginal effects (see its docstring). Each resample is drawn with replacement (whole units for panel data) and re-estimated from the estimate with the fit’s main solver, iteration cap and gradient tolerance; iter = n replaces the cap. Call it right after the fit it refers to. It takes the data and the model’s equations from the state that the last :MLE fit leaves in the backend, and the rest from result, so it stops with an error when a later sfmodel_spec or :MLE fit has replaced that state, when result comes from an earlier run of a fit that has been run again (then bootstrap the result of the new run), or when result is a deep copy of a result, such as one saved and loaded again (pass the object the fit returned). In versions before 2.0.0 a second model fitted in between went unnoticed: the function bootstrapped that model’s data with the first result’s starting values and settings, and returned wrong standard errors without a message. A fit with nothing to bootstrap (marginal = false, no inefficiency determinants, :panel_TFE_CSW, :panel_TRE) stops with “No statistics to bootstrap.”

A resample whose re-estimation fails is replaced by a new draw: the optimizer throws an error, reaches the iteration cap or stops with the gradient norm above the tolerance; computing the Hessian at its estimate throws an error, or the Hessian cannot be inverted or gives a variance that is not positive; or computing the mean marginal effects throws an error, or they contain NaN or lose a column. (In versions before 2.0.0 an error in computing the Hessian or the mean marginal effects ended the bootstrap. With Newton(), the default main solver, Optim computes the Hessian itself at every point it accepts, so an error in the Hessian at the estimate arises inside the optimizer and is counted as an error of the optimizer, except after a failed line search under Optim 2.0; see Convergence Warnings.) The results therefore come only from the resamples that converged. A resample that fails is not a random one, so when many fail the standard errors describe only the resamples that converge. An iter set too low adds to this: it keeps only the resamples that converge quickly. In bootstraps with R = 200 on two models and three data sets (3 or 4 seeds each), an iter at which 62% to 73% of the resamples failed lowered the standard errors by 13% to 22% against the default iter; where 21% to 34% failed, the standard errors moved by between +2% and -13%. The share can be large even at the default settings: for a truncated-normal model with hetero = [:mu, :sigma_u_sq] on 350 simulated observations, 20 of 50 resamples (40%) failed, 18 of them at the 200-iteration cap, and the same 20 failed with iter = 3000.

The convergence test uses the fit’s main solver; with NelderMead, NelderMead’s own convergence measure takes the place of the gradient norm. ParticleSwarm and SimulatedAnnealing always run to their iteration limit and report no gradient norm, so no resample can pass: for a fit with one of them as main solver the function stops at once with an error. Refit with a gradient-based main solver (for example Newton() or BFGS(), with ParticleSwarm() as the warmstart if wanted) and bootstrap that fit.

The function counts the failed resamples by kind:

  • after the run it prints how many resamples were drawn and how many failed of each kind (when the fit was run with verbose = true), and it issues a warning, whatever verbose, when more than 10% of the resamples drawn failed;
  • after 10R failed resamples it stops with an error that gives the counts and what to try (a larger iter; a check of the fit’s converged, redflag and gradient_norm), instead of drawing without end;
  • Ctrl-C stops it.

sf_skewness_test

sf_skewness_test(result) tests \(H_0\): the OLS residuals are not skewed, against skewness in the direction that a one-sided inefficiency term implies: negative for a production frontier, positive for a cost frontier (Schmidt and Lin 1984; Coelli 1995). Let \(e\) be the OLS residuals, \(c = e - \bar e\), \(m_2\) and \(m_3\) the second and third moments of \(c\), and \(N\) the number of observations. The normal-theory statistic is \(m_3/\sqrt{6m_2^3/N}\) (Coelli 1995; the statistic Stata reports); it assumes normal, homoscedastic noise under \(H_0\). The robust statistic is \(\sqrt{N}\,m_3/\sqrt{(1/N)\sum_i g_i^2}\) with \(g_i = c_i^3 - 3m_2c_i - m_3\), the kurtosis-robust variance of the i.i.d. case of Bai and Ng (2005); it is valid under symmetric noise with a finite sixth moment (for example Laplace, or Student-t with \(\nu > 6\)) and conservative under heteroscedastic noise. The p-values are one-sided and asymptotic: \(\Phi(z)\) for a production frontier, \(1 - \Phi(z)\) for a cost frontier. The results of both tests are at most supporting evidence of inefficiency under the maintained frontier model, not a test of the model’s specification: a misspecified frontier or omitted skewed regressors can also skew the OLS residuals. The test uses only the OLS regression of \(y\) on the frontier variables, so every fit with the same data gives the same result. It refuses panel fits, whose OLS residuals are correlated within each firm.

7.5 Hypothesis Testing

Two likelihood-ratio (LR) testing utilities are provided for fitted SF models. sf_vs_ols tests the stochastic frontier against OLS (\(H_0\): no inefficiency, \(u \equiv 0\)) in the case where the null distribution of the LR statistic is established: the cross-sectional model with normal noise, no copula and homoscedastic half-normal inefficiency (also when it is written with hetero and a zvar whose columns are all constant, not all zero), where it is \(\tfrac{1}{2}\chi^2(0) + \tfrac{1}{2}\chi^2(1)\) (Lee 1993). It raises an error for every other specification. lrtest is a general nested LR test for two fitted SF models, with an optional switch to the boundary reference. Both return an LRTestResult struct with the statistic, p-value, and pre-computed critical values.

Syntax

sf_vs_ols(result)

Arguments

Argument Type Description Required

Yes

Why sf_vs_ols refuses other models. In the other models some parameters vanish from the likelihood under \(H_0\): the truncated-normal location \(\mu\), the shape parameters of the Weibull, Gamma, Lomax and Lognormal distributions, heteroscedasticity and scaling coefficients, and copula parameters. Counting the parameters that vanish under \(H_0\) does not determine the null distribution. For the exponential, Rayleigh and Erlang distributions no published derivation of the null distribution is known. With Student-t or Laplace noise the model without inefficiency is not the normal OLS regression. Panel models are not supported. The error message names the reason. The dof keyword of versions before 2.0.0 was removed.

lrtest(...; mixed = true) refers the statistic to \(\tfrac{1}{2}\chi^2(\mathrm{dof} - 1) + \tfrac{1}{2}\chi^2(\mathrm{dof})\). This reference applies when one of the dof restrictions places a parameter on the boundary of the parameter space and every other parameter is identified under \(H_0\) (Self and Liang 1987). It does not apply when parameters vanish from the likelihood under \(H_0\), as for \(\sigma_u^2 = 0\) in a truncated-normal or heteroscedastic model.

Simulated log-likelihoods. With method = :MSLE or :MCI a fit’s log-likelihood is simulated and carries a simulation error that shrinks as n_draws grows. In an LR statistic the errors of the two fits enter as a difference. Common draws (the same method, n_draws, draw scheme and, for MCI, transformation rule) reduce the simulation error of the difference but do not remove it; when the draws differ the errors do not cancel, and when only one log-likelihood is simulated its error enters in full. lrtest compares the draw settings stored in the two results, warns when they differ or when one log-likelihood is computed without simulation, and adds a simulation line to the printed result whenever a log-likelihood is simulated. It cannot check user-supplied draws, and it does not compare inefficiency distributions: under MCI different distributions transform the same draws differently (for example the Gamma and Erlang scales), so their simulation errors need not cancel even with identical settings. To see how large the simulation error is, fit both models with sfmodel_fit(..., integration_check = true). The usual \(\chi^2\) reference for a simulated LR statistic is justified asymptotically only when n_draws grows faster than the square root of the sample size (Lee 1999), a result derived for random draws. Whatever the draws, also refit both models with more draws and check that the statistic has stopped moving, or compare with method = :MLE where the model has a closed form. sf_vs_ols prints no simulation line; for a simulated fit its result has simulated = :unrestricted.

7.7 Prediction on New Data

A fitted model can be applied to new observations through a single entry point, predict(). The what keyword selects the prediction target: the frontier value, the composed residual, the response-scale fit, the JLMS or BC efficiency index, the observation-level marginal effects, or all of the above in one call. Model Coverage

predict() works with every model the package fits, with two exceptions. First, what = :marginal is cross-sectional only: on any panel datatype it raises an informative error, and, except as below, what = :all on a panel returns the five other targets without a marginal entry. Second, a :panel_TFE fit made with method = :MLE supports only what = :frontier and :residuals: :jlms, :bc, :response and :all raise an error, so fit the model with method = :MCI or :MSLE to predict those. predict() otherwise inspects the fitted object and applies the right computation internally — you do not need to choose between methods or tune anything. For every fit whose :jlms is supported, predict() on the training data (the same X, Z, y passed at fit time) reproduces the cached result.jlms / result.bc to high precision; on new data it returns the corresponding out-of-sample quantities. Model combinations the package does not fit raise an informative error at call time.

For panel fits (:panel_TFE, :panel_TFE_CSW, :panel_TRE) you must pass id= — a vector of firm identifiers, one per observation, with rows grouped contiguously by firm (the same convention used at fit time). predict() uses it to reconstruct the panel structure and align new-data firms to the training-time firms.

Draws for new rows and new firms. predict() computes jlms and bc with the fit’s own draws. Row i of a cross-sectional frame uses the draws of row i of the estimation sample; in a frame with more rows than the estimation sample, row i uses the draws of estimation row mod1(i, N_train). In panel models a firm of the estimation sample is matched by id and uses its own draws; a new firm uses the draws of an estimation firm: the k-th new firm in the frame, in order of first appearance, uses the draws of the k-th estimation firm, restarting from the first estimation firm when there are more new firms than estimation firms.

Of the three methods, only method = :MLE computes jlms and bc without simulation: in closed form, and for :panel_TRE by one-dimensional quadrature. For its cross-sectional models (Normal noise with :HalfNormal, :TruncatedNormal including the scaling property model, or :Exponential inefficiency) and for :panel_TFE_CSW and :panel_TRE, predict() recomputes from result.coeff the same formula the fit used to populate result.jlms / result.bc, so the outputs match up to floating-point roundoff. Under :MCI and :MSLE every inefficiency distribution is simulated, :HalfNormal and :TruncatedNormal included: the fit and predict() both compute jlms and bc over the fit’s draws (which predict() reads from the result, or takes from its draws argument; see the draws row of the argument table above), so they differ from the closed form at the same coefficients by simulation error (for where that error is largest, see the MCI caveat in Choosing Between MLE, MCI, and MSLE). Use method = :MLE when exact indices are needed and the model allows it.

User-Supplied Draws

If the fit used sfmodel_method(..., draws = my_draws), the result keeps these draws (result.model), and predict() uses them when its draws argument is omitted, so it reproduces result.jlms / result.bc on the training data without further input. When my_draws already had the data’s element type and lived on the fit’s device, the fit did not copy it, and the result refers to the same array: changing my_draws after the fit changes what predict() computes. Any simulation-based fit can also pass draws to predict() to replace the stored draws, for example to explore the simulation error.

Example

# In-sample — bit-matches result.jlms and result.bc
u_hat = predict(result; frontier = X, depvar = y, zvar = Z, what = :jlms)
b_hat = predict(result; frontier = X, depvar = y, zvar = Z, what = :bc)

# Out-of-sample
out = predict(result; frontier = Xnew, depvar = ynew, zvar = Znew, what = :all)
out.jlms; out.bc; out.frontier; out.residuals; out.response

# Draws in place of the stored ones (optional for every simulation-based fit)
u_hat = predict(result; frontier = X, depvar = y, zvar = Z,
                what = :jlms, draws = my_draws)

Note on Student-t noise. \(\sigma_v\) is the scale of the \(t\) distribution \(t_\nu(0, \sigma_v)\), not its standard deviation: \(\text{Var}(v) = \sigma_v^2 \cdot \nu/(\nu - 2)\). The coefficient ln_sigma_v_sq is \(\log \sigma_v^2\) under both normal and Student-t noise, but \(\sigma_v^2\) is the noise variance only under normal noise, so the auxiliary table labels it “σᵥ² (squared scale)” for Student-t fits. Moments of order \(r\) of Student-t noise exist only for \(r < \nu\); the package keeps \(\nu > 2\), so the variance is always finite, while the third moment requires \(\nu > 3\) and the fourth \(\nu > 4\).

Laplace noise. Both MCI and MSLE evaluate \(\lvert v\rvert\) in the Laplace density as \((v^2 + 10^{-16})^{1/2}\), so each log density differs from the exact one by at most \(10^{-8}/b\). With a fixed set of draws the simulated likelihood has a kink wherever the noise value implied by a draw is zero (\(\varepsilon_i + u_{id} = 0\) for a production frontier, \(u_{id}\) the \(d\)-th draw of observation \(i\)’s inefficiency), and its maximum lies where several kinks meet. Newton’s method therefore usually stops at its iteration limit near the maximum, and the Hessian there does not measure the curvature of the likelihood. For Laplace-noise models SFrontiers (i) continues a fit that the main solver leaves unconverged with BFGS from the main solver’s endpoint and reports the convergence of this finish (result.finish; not when the main solver is BFGS() or LBFGS()), and (ii) computes the standard errors from the outer product of gradients (OPG; Berndt, Hall, Hall and Hausman 1974), labelled in the table header and in result.vcov_type. With the default optimizer settings, whether omitted or written out, the Newton stage of a Laplace-noise fit runs at most 30 iterations before this finish. main_solver = BFGS() in sfmodel_opt() skips the Newton stage, whose iterations each compute a Hessian, and is usually faster for these models.

Note on moments. Every other inefficiency distribution in the table has finite moments of all orders for every admissible parameter value. For the moments of Student-t noise, see the note under Noise Distributions.

Copula Models

Cross-sectional models only. A copula function models the dependence between the noise term \(v\) and the inefficiency term \(u\). When copula=:None (default), \(v\) and \(u\) are assumed independent. With a copula, the joint density becomes \(f(v,u) = f_v(v) \cdot f_u(u) \cdot c(F_v(v), F_u(u); \rho)\), where \(c\) is the copula density and \(\rho\) is the dependence parameter.

:Clayton90 Clayton 90° rotation \(\rho \in [10^{-6}, 50]\) \(-\rho/(2+\rho)\) Upper-lower: \(2^{-1/\rho}\) theta_rho \(= \log(\rho - 10^{-6})\)

  • Copula models are not available with noise=:StudentT (the copula density requires evaluating the Student-t CDF, to which its standard implementation is not compatible with the automatic differentiation used in the package).
  • The theta_rho initial value is on the transformed (unconstrained) scale. A value of 0.0 is a reasonable default for all copula types.
  • Clayton captures lower tail dependence (co-movement in the lower tail of distributions).
  • Clayton 90° (rotated) captures upper-lower tail dependence.
  • Gumbel captures upper tail dependence (co-movement in the upper tail of distributions).
  • Gaussian has no tail dependence but allows flexible symmetric dependence.
  • The ranges above are the ones the estimator admits, not the textbook parameter spaces. theta_rho is unconstrained and is mapped to \(\rho\) by a bounded transform: \(\rho = 0.999\tanh(\theta_\rho)\) for Gaussian, which stays inside its interval without a clamp; \(\rho = \exp(\theta_\rho) + 10^{-6}\) for Clayton and Clayton 90° and \(\rho = \exp(\theta_\rho) + 1\) for Gumbel, each of these three then clamped to the stated interval. The bounds keep \(1-\rho^2\), \(u^{-\rho}\) and \(w^{\rho}\) from underflowing or overflowing. For the Clayton, Clayton 90° and Gumbel copulas, \(\rho = 50\) is a bound: a fit that reaches it is a boundary solution, reported at 50 (see Parameter Bounds). Their lower limits, \(10^{-6}\) (Clayton) and 1 (Gumbel), are approached only as \(\theta_\rho \to -\infty\) (\(\rho\) equals them exactly in double precision only for \(\theta_\rho\) below about \(-50.6\) and \(-36.7\)). The Gaussian map \(0.999\tanh(\theta_\rho)\) is smooth, so \(\rho\) approaches \(\pm 0.999\) only as \(\lvert\theta_\rho\rvert\) grows without limit (it equals \(\pm 0.999\) exactly in double precision only for \(\lvert\theta_\rho\rvert\) above about 19.1). The strongest dependence each copula can express is Kendall’s \(\tau = 0.972\) (Gaussian), \(0.962\) (Clayton), \(-0.962\) (Clayton 90°) and \(0.980\) (Gumbel).

Parameterization

When a parameter is modeled as heteroscedastic (observation-specific), we use a link function to ensure it stays in the correct domain:

  • Linear link for parameters on \((-\infty,\infty)\). Example (truncated-normal): \(\mu_i = Z_i'\delta\).
  • Exponential link for parameters on \((0,\infty)\). Example (truncated-normal): \(\sigma_{u,i}^2 = \exp(Z_i'\gamma)\), equivalently \(\log(\sigma_{u,i}^2) = Z_i'\gamma\).

The name of the inefficiency-distribution variance

The variance parameter of the inefficiency distribution is called ln_sigma_u_sq in every estimation method, the matching heteroscedasticity option is hetero = [:sigma_u_sq], and every results table labels the row \(\sigma_u^2\). The names of versions before 2.0.0, ln_sigma_sq and hetero = [:sigma_sq], and for :Exponential also ln_lambda and hetero = [:lambda], are still accepted: SFrontiers prints a deprecation warning that names the new keyword (once per session for each old name) and uses the value unchanged. Giving an old and a new name together is an error. For :Weibull and :Lomax, ln_lambda and :lambda remain the names of their own scale.

The subscript marks the parameter as belonging to the inefficiency distribution rather than to the noise distribution. It equals \(\mathrm{Var}(u)\) only for :Exponential: for HalfNormal and TruncatedNormal it is the pre-truncation variance, and for Lognormal and Rayleigh it is that distribution’s own scale parameter. On that reading all five take the same name.

ln_lambda for Weibull and Lomax, and ln_k, ln_theta, ln_alpha and ln_sigma_v_sq, are unchanged.

Result fields have no deprecated alias. What versions before 2.0.0 stored as result.list[:ln_lambda] for panel Exponential fits, and as result.list[:ln_sigma_sq] for panel Lognormal and Rayleigh fits, is result.list[:ln_sigma_u_sq]; Exponential fits under :MCI and :MSLE report result.sigma_sq where those versions reported result.lambda; and :MLE Exponential fits report the coefficients of that parameter as result.coeff_log_σᵤ², which is also their key in result.list and in the position index result.eqpo (it was coeff_log_λ²).

Parameter Bounds

The likelihood of every simulation-based model (:MCI and :MSLE, cross-sectional and panel_TFE), and the :MLE likelihoods of panel_TFE_CSW and panel_TRE, keep some parameters within fixed numerical bounds. The optimizer works on unrestricted coefficients (the logarithm of a positive parameter), and the likelihood clamps the natural-scale value it computes from them to the bounds below. For a heteroscedastic parameter the bound applies observation by observation.

Bounds. The last column gives, for each bounded quantity, the values of its coefficient (a logarithm, named as in the coefficient table) that lie inside the bounds.

Their jlms, bc, marginal effects and predict keep \(\sigma_u^2\) and \(\sigma_v^2\) within \([10^{-12}, 10^{12}]\), so for a fit with \(\sigma_u^2\) below \(10^{-12}\) these quantities use \(10^{-12}\), which changes them only negligibly.

Why the bounds exist. The variance and scale bounds keep divisions and logarithms finite; they bind only in degenerate fits, for example when the inefficiency vanishes (\(\sigma_u \to 0\), the OLS limit) on a sample whose OLS residuals have the wrong skew. The Weibull floor \(k \ge 0.1\) keeps \(1/k\) finite in the quantile \(\lambda(-\ln(1 - r))^{1/k}\). The upper bounds of the Weibull and gamma shapes, and the gamma floor, delimit the shapes the package supports. The Lomax ceiling \(\alpha \le 100\) stops a fit of exponential-like data from running \(\alpha\) to infinity (the Lomax tends to the exponential as \(\alpha\) grows with \(\lambda/\alpha\) fixed). The Clayton ceiling keeps \(u^{-\rho}\) within double precision (with \(F\) held at \(10^{-6}\) or above, \((10^{-6})^{-50} = 10^{300}\)), and the Gumbel ceiling keeps \(w^{\rho}\) finite. The panel_TFE_CSW and panel_TRE variance bounds keep \(1/\sigma^2\) finite and the CSW integral well defined when an optimizer step drives a variance to zero.

Consequences. Beyond a bound the log-likelihood does not depend on that coefficient, so its gradient entry is exactly zero; for a homoscedastic parameter the Hessian then has a zero row and column, cannot be inverted, and every standard error of the fit is NaN. At the bound the derivative jumps from its inside value to zero. Inside the bounds the clamps do not act, and automatic differentiation gives the derivatives of the implemented likelihood (for the further kinks of the simulated objective with Laplace noise, see the notes under Noise Distributions). For a heteroscedastic parameter the bound acts observation by observation, so these kinks can lie inside the region the optimizer searches.

Boundary solutions. A fit with any parameter at or beyond its bound, within a relative tolerance of \(10^{-6}\) of the natural-scale value, is a boundary solution: redflag = 1 whatever the Hessian says (see Convergence Warnings). The message, printed with verbose = true under :MCI, :MSLE and the panel and always under :MLE, names each such parameter, its coefficient, the side and the bound, and for a heteroscedastic parameter the number and share of observations at the bound. result.bound_check records the same whatever verbose and show_table are: one entry per parameter and side, empty when no parameter is at a bound, with the fields

  • parameter (a Symbol, for example :k), label (the symbol of the bounded quantity, for example "k" or "σᵤ") and coefficient (the coefficient-table name, for example "ln_k");
  • side (:lower or :upper) and bound (the bound tested: the likelihood’s own bound, or the simulation methods’ bound for the :MLE models whose likelihoods have none);
  • scalar (true for a homoscedastic parameter), n_at and n (the observations at or beyond the bound, and all observations; equal for a homoscedastic parameter) and share (n_at/n);
  • moved and coef_before (see Reported coefficients).

result.hessian_flag holds the Hessian part of redflag (0, 1 or 2) before the boundary rule, so a boundary solution with a regular Hessian (a heteroscedastic parameter at a bound at some observations, or a parameter within the tolerance) can be told from a Hessian failure.

Standard errors. A homoscedastic parameter beyond a bound that its likelihood applies makes every standard error NaN, because the Hessian is singular. A parameter inside its bound but within the tolerance, a heteroscedastic parameter at a bound at some observations, and a parameter of the other :MLE models (whose likelihoods have no bounds) keep the standard errors as computed.

Reported coefficients. A homoscedastic coefficient that ends beyond a bound its likelihood applies is reported at the bound. After the Hessian has been computed at the optimizer’s point, the coefficient is replaced by the one whose natural-scale value lies at the bound (beyond it by a relative \(10^{-12}\), so that the likelihood still uses the bound itself). The log-likelihood, the gradient, the Hessian and the other coefficients do not change, and the coefficient table, the auxiliary table and the copula table show the value the likelihood used (for example \(\alpha = 100.0000\), with standard error NaN). The entry in bound_check then has moved = true and keeps the optimizer’s coefficient in coef_before. A heteroscedastic coefficient is never moved, nor is a coefficient of the other :MLE models, whose likelihoods have no bounds.

Starting values. sfmodel_fit refuses starting values at or beyond a bound that the likelihood applies to a homoscedastic parameter (every :MCI and :MSLE model, cross-sectional and panel_TFE, and the panel_TFE_CSW and panel_TRE variances under :MLE), with an error that names the parameter, its init keyword, the value and the bounds: beyond a bound a gradient-based optimizer cannot move the coefficient. When the starting values put a heteroscedastic parameter at or beyond its bound at some observations, a warning gives their number and the fit proceeds. The starting values of the other :MLE models are not checked. A fit held at its starting values (no warmstart stage and iterations = 0 in the main stage) runs no optimizer and is not checked; it remains the way to evaluate the outputs at given coefficients. A refit of a boundary solution must start inside the bound: the reported coefficient of a moved fit is at the bound and is refused as a start.

The Gaussian copula. Its map \(\rho = 0.999\tanh(\theta_\rho)\) is smooth and bounded, so it has no bound to reach: \(\rho\) approaches \(\pm 0.999\) only as \(\lvert\theta_\rho\rvert\) grows without limit.

Inefficiency Distribution

The choice of inefficiency distribution affects the shape of the estimated inefficiency, particularly its mode and tail behavior. The following table summarizes the key properties:

Rayleigh 1 (\(\sigma\)) No (mode > 0) Light One-parameter distribution with mode away from zero

Practical workflow:

  1. Start simple. Begin with half-normal or Exponential. These one-parameter distributions are easy to estimate (MLE available) and serve as a baseline.
  2. Allow non-zero mode. If theory suggests that most firms have some positive level of inefficiency (rather than clustering near zero), try truncated-normal, Rayleigh, or an Erlang order (:Erlang2, :Erlang3, :Erlang4; the mode moves away from zero as the order rises while \(\theta\) remains the only estimated parameter).
  3. Add flexibility. If one- or two-parameter distributions seem restrictive, try Weibull, Lognormal, or Gamma. These can capture a wider variety of shapes but require simulation-based estimation (MCI or MSLE).

Why Gamma is MCI only. MSLE draws the inefficiency values through the quantile (inverse-CDF) function, \(u_d = Q(t_d; \text{parameters})\). For Gamma the estimated shape \(k\) sits inside the quantile, so the (numeric) inversion would have to be repeated inside every likelihood evaluation, at every optimizer iteration, with automatic differentiation flowing through it; that computation is slow, scalar, and incompatible with the GPU pipeline, so Gamma is not offered under MSLE. Erlang escapes this: its shape is pinned at the integer \(m\), \(\theta\) is a pure scale, and \(Q(p; m, \theta) = \theta \cdot q_m(p)\) with the standardized quantile \(q_m\) a function of the fixed draws only, evaluated by a fast, GPU-compatible Newton iteration that no estimated parameter (and hence no derivative) ever enters.

When to use MLE: If your model uses Normal noise with half-normal, truncated-normal, or Exponential inefficiency (and no copula), MLE is the natural first choice — it is exact (no simulation error), fast, and does not require tuning the number of draws.

When to use MCI/MSLE: For models that MLE cannot handle (non-Normal noise, copula dependence, Weibull/Lognormal/Lomax/Rayleigh/Gamma/Erlang inefficiency), the simulation-based methods are required. For models supported by all three methods, MLE and simulation estimates typically agree closely.

For a given model supported by both MCI and MSLE, the two simulation methods typically produce similar estimates. Differences may arise because MCI and MSLE use different likelihood constructions, so they can respond differently to the choice of distribution, sample size, and starting values. In particular, when the data do not conform well to the assumed distributional shape, the finite set of simulation draws may cover the tails unevenly, causing the two methods to weight those observations differently.

Caveat: MCI, the draw transformation, and its scale. MCI evaluates the likelihood by importance sampling: a uniform draw t is mapped to an inefficiency value u through a fixed transformation whose width is set by a per-family scale parameter, and the integrand is reweighted by that transformation’s Jacobian. Accuracy at a given n_draws therefore depends on how well the transformation’s scale matches where the fitted distribution puts its mass. When the two are far apart, the importance weights concentrate on a handful of draws, or every draw lands where the integrand is negligible, and the likelihood, jlms and bc can be far from their exact values even though the fit reports convergence. Symptoms: bc pinned at exactly 1.0 and implausibly small jlms. The integration check tests the accuracy of the simulated log-likelihood at the estimate; use it whenever a fit falls in one of the situations below. SFrontiers also prints a warning when the per-observation effective sample size of the jlms/bc importance weights falls below 10. With Halton draws such small values also occur when jlms, bc and the likelihood are accurate, so the warning flags a potential numerical issue and does not establish that the fit is affected; the integration check tells whether it is.

The first situation is a concentrated truncated-normal inefficiency (including the scaling property model): the transformation’s draws thin out as u grows and end near σᵤ × n_draws, so if the estimated distribution concentrates far out, beyond that range or, when the noise is small, merely where the draws are sparse (large μ/σᵤ, an almost deterministic inefficiency level, which some data can produce as a fitting corner), the draws miss the mass. In simulated samples of 500 observations with σᵥ equal to the spread of u or 0.3 times it, the MCI log-likelihood at the true parameters and 8,192 draws was within 0.015 nats of the exact value for μ/σᵤ from −6 to 10; at μ/σᵤ = 100 it was 65 to 86 nats off with σᵥ 0.3 times the spread and about 2,400 with a tenth of it. Increase n_draws substantially or, usually better, refit with method = :MSLE, whose inverse-CDF draws follow the estimated distribution and so cover where its mass is; :MLE, where the model is supported, is also immune. With shared draws (multiRand = false) every observation uses the same draws, and when the inefficiency distribution is concentrated the simulated MCI objective can have spurious maxima, points where one draw falls on the narrow mode for every observation and the simulated log-likelihood lies far above the exact one, at which a fit can stop with converged = true and redflag = 0; the integration check flags them. MSLE has a coverage limit of its own, though, and no effective-sample-size warning: its draws reach only as far as the upper quantiles of the estimated distribution. At an observation far in the upper tail of the fitted inefficiency distribution (a large negative residual for a production frontier), beyond the largest draws, MSLE’s simulated likelihood of that observation is too low, which also pulls its estimates and its log-likelihood level, and its simulated jlms is too small; more draws help little when that tail is thin, while MCI, whose transformation reaches much farther, stays accurate there.

The second is the mirror case, a truncated normal far in its lower tail. When μ/σᵤ is very negative the density piles up within about σᵤ/|μ/σᵤ| of zero, far inside the transformation’s scale σᵤ, so few draws land where the mass is. In such samples at μ/σᵤ = −20 and −50, the log-likelihood at 8,192 draws was up to 0.066 nats off under MCI with the default rule and up to 0.0013 under MSLE. Where a fit heads that far, use method = :MSLE or :MLE, which are accurate there.

With a copula the MCI draw error is larger than without. Take particular care with a copula fit, under MCI or MSLE, that ends with the copula parameter at its bound (in the examples checked, a Gaussian ρ of ±0.999, often with σᵤ or σᵥ collapsing toward 0): there the simulated log-likelihood can be too high, the optimizer is drawn to it, and the fit may still report convergence. Run the integration check on such a fit before using its log-likelihood or estimates.

The effective-sample-size warning has a limitation worth knowing: it fires on weights that collapse onto a few draws, but not when a transformation is merely too wide and every draw lands where the integrand is negligible, and such a fit can pass it while sitting more than a nat from the exact integral. The integration check compares the log-likelihood itself at two numbers of draws, so it responds once the larger set reaches where the integrand matters. panel_TFE models print no effective-sample-size warning; use the integration check for them. If a comparison of log-likelihoods across inefficiency families matters for your conclusion, run the integration check on each fit.

Shape ranges where MCI is unreliable. Under the default transformation rules (:expo_rule for the Gamma and the Weibull, :logistic_1_rule for the Lomax), three ranges of the inefficiency shape are hard for MCI’s draws, whatever their scale, and one range is hard for MSLE at the default number of draws. After a fit whose estimate lies in one of them, SFrontiers prints a warning that names the alternatives; the warning flags a potential numerical issue and does not establish that the fit is affected; the integration check tells whether it is. Every Gamma, Weibull and Lomax MCI fit under the default rule, and every Lomax MSLE fit, stores the verdict in result.shape_check: the threshold, whether the estimate lies below it, and for a heteroscedastic shape how many observations do and the smallest value (nothing for other families and rules); shape_warning = false in sfmodel_fit() or sfmodel_panel_fit() turns the warning off, and the verdict is stored either way. Cross-sectional and panel_TFE models are covered alike. The figures below are at the true parameters of simulated data, 500 observations (100 firms with 6 periods in panel_TFE models), with the default 4,096 draws unless stated.

  • A Gamma shape k below 0.6 (MCI, :expo_rule). The Gamma density behaves like u^(k−1) near zero, while the draws of :expo_rule (and of :logistic_1_rule) have a finite density there, so the importance weights behave like u^(k−1) too: for k ≤ 0.5 they have infinite variance, and no choice of scale makes the likelihood accurate. In this range k̂ tends to come out too high, so a fit can end above the threshold and the warning can miss it; the integration check is the general detector. In the samples the log-likelihood was off by up to 230 nats below k = 0.6 and by at most 0.24 nat from k = 0.6 up, except in one sample at k = 1 with an observation beyond the reach of 4,096 draws (3.7 nats off; 0.041 at 8,192 draws); in the panels, by up to 2.2 nats at k = 0.3 and at most 0.090 from 0.5 up. GPU Computation

GPU acceleration is available for the simulation-based methods (MCI and MSLE) and is highly recommended when the number of draws or the sample size is large. MLE does not use GPU, because its likelihood needs no simulation draws: it is evaluated in closed form, and for :panel_TFE_CSW and :panel_TRE by a one-dimensional quadrature per firm.

Why GPU helps. Simulation-based estimation evaluates the likelihood contribution for every combination of \(N\) observations and \(D\) draws, forming an \(N \times D\) matrix. These element-wise operations are massively parallel and map naturally onto GPU architectures. In practice, enabling GPU can reduce estimation time from minutes to seconds.

Requirements:

  1. An NVIDIA GPU with a compatible driver installed on the machine.
  2. The Julia package CUDA.jl (using CUDA), version 6.4 or earlier (see Section 3). Julia 1.10 or later is required.
  3. CUDA.jl must be loaded before SFrontiers.jl in every session. SFrontiers detects CUDA at load time; if the order is reversed, GPU features will not be available and you must restart Julia (see Section 3).

Usage:

using CUDA          # must come before SFrontiers
using SFrontiers

meth = sfmodel_method(
    method = :MSLE,    # 4,096 Halton draws per observation by default
    GPU = true,        # enable GPU acceleration
    chunks = 10        # process the observations in 10 groups; bounds memory
)

Managing GPU memory with chunks. The likelihood, its derivatives and the efficiency indices are computed for one group of about N/chunks observations (firms, in panel models) at a time, so their memory falls in proportion to chunks; About GPU and chunks options gives the formula. Before the optimizer starts, a GPU fit prints a warning that names chunks and n_draws when its estimate of that memory exceeds the free GPU memory. Start with the default (chunks = 10) and raise it when the warning appears or a fit runs out of memory; each additional chunk adds a fixed cost to every evaluation. On Windows, Task Manager can be used to monitor VRAM usage in real time.

Tip: The chunks option also works on CPU and can help with large datasets even without a GPU.

GPU memory across fits. Each likelihood evaluation of an MCI or MSLE GPU fit allocates new device arrays of one group’s size (the work arrays of About GPU and chunks options), plus smaller ones when the last group is shorter. Under the default Newton() main solver the likelihood is also evaluated on nested ForwardDiff dual numbers to form the Hessian, and every element of these arrays then holds many numbers, so the arrays are large. CUDA.jl keeps freed arrays in its memory pool, and Julia’s garbage collector does not track device memory, so it may not free them in time: fits run side by side in one Julia process can fill the card. JULIA_CUDA_SOFT_MEMORY_LIMIT does not prevent this; it is the pool’s release threshold, not a cap. Calling GC.gc() and then CUDA.reclaim() after each fit releases that memory between fits, but one long fit can still grow the pool by itself. In one study of MCI GPU fits with 8,192 draws and n = 1,220 on a 32 GB card, made with an earlier version that allocated more device memory per evaluation, with the soft limit at 16 GiB and no collection, 6 and 4 concurrent fits reached 31,981 and 32,091 of the card’s 32,607 MiB. Collecting after each fit still left peaks of 24,205, 24,613 and 32,069 MiB in three runs of one stage at 4 concurrent fits, because one long Nelder-Mead solve grew the pool between fits. That study’s driver therefore also ran the same two calls from a separate task whenever memory use was high, and with both, later runs stayed between about 11.8 and 21.2 GB with no out-of-memory error. A fitted result keeps its draw matrix on the GPU (the model field), so a program that keeps many GPU results also keeps their draws on the card; keep only the fields you need.

Numerical precision. GPU computation uses the same precision as the CPU path, so enabling GPU = true does not trade accuracy for speed: in a fit the coefficients are Float64 on the GPU as on the CPU, and so is the arithmetic of the likelihood, whatever the element type of the data (for Float32 data, see below). For the same specification and draws, with Float64 data, the likelihood evaluated on GPU matches the CPU value to machine precision (differences on the order of \(10^{-13}\) or smaller). The package’s CPU–GPU equivalence sweep checks this for every inefficiency distribution, several chunk settings, the copulas and the panel model; test/GPU_VALIDATION.md gives the command, the tolerances and the recorded release run. Estimated coefficients and efficiency indices agree equally closely; in nearly flat regions of the likelihood (e.g., a copula dependence parameter near zero), a CPU and a GPU run may stop at slightly different coefficient values with identical log-likelihoods — this reflects the optimizer’s stopping point, not GPU precision loss. With Float32 data the GPU and CPU likelihoods can differ by more, at least with a copula: on one sample of 300 observations (truncated-normal inefficiency, Gaussian copula with \(\rho \approx 0.46\), 1,024 draws per observation taken from a Halton sequence of \(2^{15} - 1\) points recycled across observations, the construction of versions before 2.0.0), the GPU log-likelihood differed from the CPU one by up to \(1.739 \times 10^{-8}\) nats under :MCI and \(1.392 \times 10^{-6}\) nats under :MSLE, at most \(2.3 \times 10^{-9}\) of its value; the cause has not been established. Single-precision (Float32) data are accepted: the specification stores them in single precision, and the package computes the Halton points in double precision, rounds them to single precision and keeps every draw below 1. The optimizer’s parameter vector is always Float64, on the CPU and on the GPU, so a fit evaluates the likelihood in double precision from these single-precision inputs (only steps that act on the draws alone run in single precision: under :MCI the draw part of the change of variables, such as \(\log(1-t)\) and \((1-t)^2\) for a draw \(t\), and under :MSLE the inverse error function of the draws (in the half-normal and lognormal quantiles and in the Gaussian copula’s scores of the draws), the draw part of the exponential, Weibull, Rayleigh and Lomax quantiles (such as \(\log(1-r)\) for a draw \(r\)), the factor \(1-r\) of the truncated-normal quantile where \(\mu/\sigma \ge -8\sqrt2\), the Erlang quantile at unit scale and the logarithms of the draws in the Clayton, Clayton90 and Gumbel copulas), and the coefficients, standard errors, log-likelihood, result.jlms, result.bc and marginal effects are returned as Float64 whatever the data’s element type. The inputs of the likelihood, however, keep the specification’s element type — the data, the draws and the precomputed constants alike — so a Float32 fit is not a double-precision computation on rounded data alone: holding the data bit-identical as real numbers and the parameter vector in Float64, the two specifications still return different log-likelihoods, because the constants differ in the eighth significant figure. A Float32 fit of a model without a copula therefore agrees with the Float64 fit of the same data to order \(10^{-7}\) rather than \(10^{-13}\). That figure is measured, not asserted: over truncated-normal MSLE fits at true \(\mu\) of \(+0.1\), \(-1\), \(-2\), \(-3\), \(-4\) and \(-6\) with \(\sigma_u = 0.5\), the largest single-coefficient gap between the two element types is \(5.2\) to \(6.0 \times 10^{-8}\) throughout. Those fits had normal noise. Copula models agree to about the same order, for moderate \(\rho\); the gap grows as \(\rho\) approaches 1. A fit computes the noise and inefficiency probabilities in double precision from its Float64 parameter vector, and the copulas’ clamps follow the precision in which each probability is computed (:MSLE’s stored draws keep a single-precision inverse error function, with bounds that do not cap them). Clamps of the data’s element type would cap the Gaussian copula’s normal scores of these probabilities at about \(\pm 4.62\) in a Float32 fit against \(\pm 7.78\) in a Float64 fit, and cut the Gumbel copula’s probabilities off at \(1 - 6.0 \times 10^{-8}\) instead of \(1 - 1.1 \times 10^{-16}\); under :MSLE they would also cap the scores of the draws, which are stored in single precision and which Halton sequences of \(2^{20}\) points or more, and user-supplied draws, bring within \(1.9 \times 10^{-6}\) of 0 or 1. At the same coefficients and 1,024 draws, on four samples of 250 to 500 observations, such clamps made the two log-likelihoods differ by up to 2.3 nats at \(\rho \approx 0.5\) and by 4 to 380 nats at \(\rho \approx 0.96\) with the Gaussian copula, under :MCI and :MSLE alike, and by up to \(4.05 \times 10^{-3}\) with the Gumbel copula under :MCI. At the same points the two log-likelihoods differ by at most \(3.54 \times 10^{-7}\) of their value for \(\rho\) up to 0.963 and \(2.09 \times 10^{-6}\) at \(\rho = 0.994\) with the Gaussian copula, by at most \(1.03 \times 10^{-4}\) nats with the Gumbel copula, and by at most \(2.01 \times 10^{-4}\) with the Clayton and Clayton90 copulas, about as much as without a copula (at most \(9.53 \times 10^{-5}\)). Near the bound the remainder depends on the sample: it comes from the Float32 rounding of the other constants, which the copula term amplifies about as \(1/(1 - \rho^2)\), and reached \(6.6 \times 10^{-6}\) of the log-likelihood at \(\rho = 0.994\) on another sample. With Halton sequences of \(2^{20}\) to \(2^{24}\) points (1,024 to 4,096 draws, 1,100 to 4,200 observations) the Gaussian copula’s gap under :MSLE was at most \(2.29 \times 10^{-6}\) for \(\rho\) up to 0.994; at \(\rho = 0.963\) on half-normal data most of it comes from the single-precision inverse-erf clamp of the half-normal quantile (below), which such sequences reach. Complete fits at 1,024 draws of two half-normal samples of 250 and 400 observations with the Gaussian copula agree between the two element types to at most \(6.94 \times 10^{-7}\) in any coefficient, against \(1.86 \times 10^{-5}\) to \(2.58 \times 10^{-4}\) with clamps of the data’s element type. Finally, predict() recomputes in double precision on the CPU, so it reproduces the result.jlms of a Float64 fit run on the CPU bit for bit, but that of a GPU fit only to double-precision rounding and that of a Float32 fit only to single-precision rounding. The arithmetic is double precision, but the precomputed constants and the draws stored on the result are taken at the fit’s own element type and then widened, because several of those constants are numerical guards rather than scale factors — the inverse-erf clamp \(1 - 32\,\varepsilon(T)\), for one, sits at \(0.999996\) in Float32 and \(1 - 7.1 \times 10^{-15}\) in Float64. (That clamp bounds the half-normal and lognormal quantiles, whose argument is the draw itself; the truncated-normal quantile is computed as \(u = \mu + \sigma\sqrt{2}\,\mathrm{erfcinv}\!\left(\mathrm{erfc}(-\mu/(\sigma\sqrt2))(1-r)\right)\), which never forms a number near \(1\) and so is not clamped at all. Below \(\mu/\sigma = -8\sqrt2 \approx -11.3\), where \(\mathrm{erfc}(-\mu/(\sigma\sqrt2))\) heads for underflow (it is subnormal below \(\mu/\sigma \approx -37.5\) and \(0\) below \(-38.5\) in Float64, where that formula returns infinite draws), the draw is instead \(\sigma\sqrt2\,t\), with \(t\) the root of \(\mathrm{erfc}(y+t) = (1-r)\,\mathrm{erfc}(y)\), \(y = -\mu/(\sigma\sqrt2)\), found by Newton’s method on the scaled function \(\mathrm{erfcx}\), which also runs on the GPU. In the inverse-error-function form the clamp \(1 - 32\,\varepsilon(T)\) would cap \(u\) at \(\mu + 4.62\sigma\) in Float32 and \(\mu + 7.78\sigma\) in Float64. Versions before 2.0.0 computed the :MSLE truncated-normal draws in that form, clamped, in Float64, so for \(\mu/\sigma\) below about \(-7.8\) all their draws saturated; in Float32 every draw would saturate below about \(-4.6\), \(\mu\) would stop being identified, and the two element types would disagree by up to \(1.06\) in a coefficient rather than by \(10^{-7}\).) Rebuilding them at Float64 would make predict() evaluate a different integrand from the one the fit maximised, not a more precisely rounded one. The Float32 path exists for GPU memory, not for speed: on CPU it is not faster. What it saves is the storage of the data and the draws, not the work arrays of the likelihood, which are Float64 with either element type because the coefficients are: in one measurement on the CPU (2,000 observations, 1,024 draws, half-normal inefficiency, :MCI and :MSLE, without a copula and with a Gaussian copula), one likelihood evaluation and one gradient at Float64 coefficients allocated as much memory with Float32 data as with Float64 data, while the stored draws took 7.8 MiB instead of 15.6 MiB.

Results live on the CPU. All fields of a GPU fit’s result — coefficients, standard errors, result.jlms, result.bc, and marginal effects — are returned as ordinary CPU arrays. Post-estimation analysis (indexing, plotting, DataFrame construction, predict) therefore works exactly as after a CPU fit. The exception is result.model, the internal specification, which keeps the data and the draw matrix on the GPU; predict() copies one group of rows at a time to the host.

Copula Models

To model dependence between the noise and inefficiency terms, specify a copula:

# Clayton copula (lower tail dependence)
spec = sfmodel_spec(
    type = :production,
    depvar = y,
    frontier = X,
    noise = :Normal,
    ineff = :HalfNormal,
    copula = :Clayton,
)

# Initial values must include theta_rho for the copula parameter
myinit = sfmodel_init(
    spec = spec,
    frontier = X \ y,
    ln_sigma_u_sq = [0.0],
    ln_sigma_v_sq = [0.0],
    theta_rho = [0.0]       # copula dependence parameter (transformed scale)
)

# Clayton 90° rotated copula (upper-lower tail dependence)
spec_c90 = sfmodel_spec(
    type = :production,
    depvar = y,
    frontier = X,
    noise = :Normal,
    ineff = :HalfNormal,
    copula = :Clayton90,
)

# Gumbel copula (upper tail dependence)
spec_g = sfmodel_spec(
    type = :production,
    depvar = y,
    frontier = X,
    noise = :Normal,
    ineff = :Exponential,
    copula = :Gumbel,
)

The estimation output includes a copula auxiliary table showing:

  • \(\rho\): the dependence parameter (on the original scale) with standard error
  • Kendall’s \(\tau\): rank correlation measure
  • Tail dependence coefficient

Tail dependence by copula type:

Copula Tail Dependence Interpretation
Gaussian None (symmetric, no tail dependence) Dependence is moderate and evenly spread; no extreme co-movement in the tails
Clayton Lower tail Firms at the low end of \(v\) (e.g., negative shock) and low end of \(u\) (e.g., efficient) move together.
Clayton 90° Upper-lower (rotated) Firms at the high end of \(v\) (e.g., positive shock) and low end of \(u\) (e.g., efficient) move together.

Note: Copula models are supported only for cross-sectional data. Student-t noise is not compatible with copulas (the copula density requires evaluating the Student-t CDF, to which its standard implementation is not compatible with the automatic differentiation used in the package).

Identification and testing

The dependence parameter \(\rho\) is identified only through the assumed marginal distributions of \(v\) and \(u\) and the assumed copula.

Copula fits need enough draws. Refit a copula model with a larger n_draws and check that the estimates and the log-likelihood do not move materially. The integration check (sfmodel_fit(..., integration_check = true)) makes this comparison without a refit: it reports how much the log-likelihood at the estimate changes with four times the draws, and estimates how far, in standard errors, a refit with that many draws would move the coefficients.

The z statistic printed for theta_rho tests theta_rho = 0. For the Gaussian copula this is independence (\(\rho = 0\)), but the test can mislead when identification is weak. For the Clayton and Clayton 90° copulas, theta_rho = 0 means \(\rho \approx 1\), that is, Kendall’s \(\tau \approx 1/3\) (Clayton) or \(-1/3\) (Clayton 90°); for the Gumbel copula it means \(\rho = 2\) (\(\tau = 1/2\)). For these three copulas the printed z statistic does not test independence.

For the Clayton, Clayton 90° and Gumbel copulas, independence lies on the boundary of the parameter space (\(\rho \to 0\) for Clayton and Clayton 90°, \(\rho = 1\) for Gumbel), so the usual \(\chi^2\) reference distribution of a likelihood-ratio test of independence may not apply (Self and Liang 1987; Andrews 1999). When a copula model is compared with the model without a copula (copula = :None), fit both with the same, sufficient number of draws.

Scaling Property Model (Cross-Sectional)

The scaling property model introduces observation-specific heterogeneity through a single multiplicative scaling function, rather than making individual distributional parameters heteroscedastic:

\[ u_i = h(\mathbf{z}_i) \cdot u_i^*, \qquad h(\mathbf{z}_i) = \exp(\mathbf{z}_i'\boldsymbol{\delta}), \]

where \(u_i^*\) follows a homoscedastic (scalar-parameter) base distribution and \(\mathbf{z}_i\) is a vector of environmental/exogenous variables. The scaling function \(h(\mathbf{z}_i)\) is always positive and rescales the base inefficiency without changing the distributional shape.

Key mathematical properties:

  1. Jacobian cancellation: The change of variable \(u_i = h_i u_i^*\) produces a Jacobian \(h_i\) that cancels with the \(1/h_i\) from the density transformation \(f_u(u_i) = \frac{1}{h_i} f_{u^*}(u_i/h_i)\), leaving \(f_{u^*}(u_i^*)\) directly in all integrals.
  2. JLMS factorization: \(E(u_i \mid \varepsilon_i) = h_i \cdot E(u_i^* \mid \varepsilon_i)\).
  3. BC non-factorization: \(E(e^{-u_i} \mid \varepsilon_i) = E(e^{-h_i u_i^*} \mid \varepsilon_i)\); the \(h_i\) must remain inside the exponential.
  4. Semi-elasticity: \(\partial \ln E(u_i) / \partial \mathbf{z}_i = \boldsymbol{\delta}\), where \(E(u_i^*)\) exists, providing direct interpretation of the scaling coefficients.

Unconditional mean \(E(u_i) = h(\mathbf{z}_i) \cdot E(u_i^*)\), where \(E(u_i^*)\) depends on the base distribution:

Distribution \(E(u_i^*)\)
half-normal \(\sigma\sqrt{2/\pi}\)
truncated-normal \(\sigma_u(\Lambda + \phi(\Lambda)/\Phi(\Lambda))\), \(\Lambda = \mu/\sigma_u\)
Exponential \(\sigma_u = \sqrt{\sigma_u^2}\)
Weibull \(\lambda\,\Gamma(1 + 1/k)\)
Lognormal \(\exp(\mu + \sigma^2/2)\)
Lomax \(\lambda / (\alpha - 1)\) for \(\alpha > 1\); does not exist for \(\alpha \le 1\) (marginal effects are then NaN)
Rayleigh \(\sigma\sqrt{\pi/2}\)
Gamma \(k\theta\)
Erlang (\(m\)) \(m\theta\)

Identification constraint: The zvar matrix must not contain a constant column. A constant in \(\mathbf{z}_i\) would create an intercept that is not separately identified from the scale parameter of the base distribution (e.g., \(\sigma_u\) in half-normal or in Exponential).

Supported distributions: All inefficiency distributions are supported under method = :MCI and :MSLE; the Gamma distribution requires method = :MCI. Under method = :MLE the scaling model is available for :TruncatedNormal only — for any other ineff, no MLE specification is built and the fit reports which methods are available.

Usage Example

# Step 1: Specify a scaling property model
spec = sfmodel_spec(
    type = :production,
    depvar = y,
    frontier = X,                 # include constant
    zvar = Z_nocons,              # environmental variables (NO constant!)
    noise = :Normal,
    ineff = :HalfNormal,
    hetero = :scaling,            # activates scaling property model
)

# Step 2: Choose estimation method (MSLE and MCI work for every distribution;
#         MLE works here only for ineff = :TruncatedNormal)
meth = sfmodel_method(
    method = :MSLE,
    GPU = true,
    chunks = 10
)

# Step 3: Set initial values — note the "scaling" keyword for δ
init = sfmodel_init(
    spec = spec,
    frontier = X \ y,
    scaling = zeros(size(Z_nocons, 2)),   # δ initial values
    ln_sigma_u_sq = [0.0],                  # scalar base parameter
    ln_sigma_v_sq = [0.0]
)

# Step 4: Configure optimization
opt = sfmodel_opt(
    warmstart_solver = NelderMead(),
    warmstart_opt = (iterations = 200,),
    main_solver = Newton(),
    main_opt = (iterations = 100, g_abstol = 1e-8)
)

# Step 5: Estimate
result = sfmodel_fit(
    spec = spec, method = meth, init = init,

# Access scaling coefficients
println("δ coefficients: ", result.delta)

# Marginal effects (computed via ForwardDiff)
println("Mean marginal effects: ", result.marginal_mean)
println("Observation-level marginal effects: ", result.marginal)

Mathematical Difference

The key difference between production and cost frontiers lies in the sign of the inefficiency term:

  • Production frontier: \(\varepsilon_i = v_i - u_i\) (inefficiency reduces output)
  • Cost frontier: \(\varepsilon_i = v_i + u_i\) (inefficiency increases cost)

The software handles the sign convention internally when type = :cost is set. All post-estimation quantities (JLMS, BC, marginal effects) are computed correctly for cost frontiers without additional user adjustments.

Common Pitfall: Wrong-Sign Skewness

Before estimating a stochastic frontier model, check the OLS residual skewness (reported in the sfmodel_fit() output as OLS_resid_skew):

  • For a production frontier, the OLS residuals should be negatively skewed. This is the pattern that one-sided inefficiency pulling output below the frontier produces under the maintained frontier model; sf_skewness_test(result) gives the one-sided test.
  • For a cost frontier, the OLS residuals should be positively skewed, the pattern that inefficiency pushing costs above the efficient level produces.

If the skewness has the wrong sign, the data may not support the presence of inefficiency in the assumed direction, and the model may have difficulty converging or produce unreliable estimates.

Choosing the Number of Halton Draws

The number of draws per observation, n_draws, affects accuracy and computing time. Use powers of two (see Observation-Specific Halton Draws). The following is a rough reference.

n_draws Typical use
256 (2^8) Checking that a specification runs
1,024 (2^10) Exploratory fits on a CPU; very large samples when time or memory is short (confirm the final estimates at the default)
4,096 (2^12) Default; estimates to report
32,768 (2^15) Checking that the results do not move with the number of draws

The table is a within-model guide. Comparing log-likelihoods ACROSS families is a stricter requirement, and the table does not cover it. Under MCI each family carries its own integration error at a given n_draws, and only the DIFFERENCES between families matter for a comparison, an information criterion, or a model-averaging weight. An error that is common to every candidate cancels; one that varies by family does not. So if a cross-family ranking is load-bearing, do not read it off a single run: repeat it at a substantially larger n_draws and confirm the differences have stopped moving. MLE, where supported, avoids the issue, which does not arise at all for families whose likelihood SFrontiers evaluates without simulation. MSLE has no transformation-scale error, but it has a simulation error of its own that also depends on the family and the data: the far-tail error described in the MCI caveat of Choosing Between MLE, MCI, and MSLE, and on some data a larger draw error than MCI’s. So check a cross-family comparison under MSLE the same way.

Number of draws and computing cost. The default, n_draws = 4096 (2^12) per observation (per firm in panel models), is chosen for accuracy. Computing time and memory grow in proportion to the number of observations (firms) times n_draws. On one CPU core, a complete fit of a normal–truncated-normal model with 500 observations took about 61 seconds under :MSLE at the default, against about 12 seconds with 1,024 draws; :MCI took about as long at the default. Memory is set by chunks; About GPU and chunks options gives the formula. To reduce time or memory: raise chunks (memory falls in proportion; time rises slightly); use the GPU; or, for exploratory work on a CPU or for a very large sample, lower n_draws to a smaller power of two such as 1,024 or 2,048 and confirm the final estimates at the default. To check that a fit’s draws suffice, turn on the integration check (integration_check = true in sfmodel_fit()), which re-evaluates the fit with four times as many draws, or refit with n_draws = 2^15 and confirm that the results have stopped moving.

meth = sfmodel_method(
    method = :MSLE,
    n_draws = 2^15    # 32,768 draws: check that the results have stopped moving
)

Observation-Specific Halton Draws (multiRand)

Simulation-based estimation (MCI and MSLE) approximates the likelihood by drawing simulated inefficiency values \(\{u_i^d\}\), \(d = 1, \ldots, D\), for each observation \(i\), from a set of uniform draws \(\{r_i^d\} \in (0, 1)\). The two methods turn those uniforms into inefficiency values differently, and the difference matters for accuracy. MSLE uses inverse transform sampling: \(u_i^d = F^{-1}(r_i^d)\), where \(F^{-1}\) is the inverse CDF (quantile function) of the assumed inefficiency distribution, so the simulated values follow that distribution exactly. This works because if \(r\) is uniformly distributed on \((0, 1)\), then \(F^{-1}(r)\) follows \(F\). MCI instead maps each uniform through a fixed transformation with a per-family scale and reweights the integrand by that transformation’s Jacobian, which is what keeps the likelihood differentiable by ForwardDiff and computable on a GPU for every family, including those whose quantile function has no closed form in the estimated parameters. The cost is that MCI’s accuracy at a given \(D\) depends on how well the transformation’s scale matches where the fitted distribution puts its mass; see the caveat in Section 9, “Choosing Between MLE, MCI, and MSLE”.

Instead of pseudo-random uniform draws, the package uses the base-2 Halton sequence (the van der Corput sequence) φ(1), φ(2), φ(3), … = 1/2, 1/4, 3/4, 1/8, 5/8, …, a deterministic low-discrepancy sequence that covers the interval (0, 1) more evenly than random sampling. The draws of an observation are fixed across the iterations of the optimizer and differ across observations. With multiRand = true (the default) the package generates the first Q = N × D points of the sequence, where D = n_draws, and gives observation i the D consecutive points φ((i − 1)D + 1), …, φ(iD): observation 1 receives points 1 to D, observation 2 points D + 1 to 2D, and so on. No point is used twice. In panel models i indexes firms. This is the construction of Bhat (2001) and Train (2000; 2009, Section 9.3.3). With multiRand = false every observation receives the same first D points.

Powers of two. Any 2^m consecutive points of the base-2 sequence contain exactly one point in each interval [(k − 1)/2^m, k/2^m), k = 1, …, 2^m, wherever they start in the sequence. When D is a power of two, the draws of every observation therefore spread evenly over (0, 1); under recycling (below), a segment that crosses a restart of the sequence loses this property. The default, D = 4,096 = 2^12, is a power of two, and other values of n_draws should be powers of two as well.

Precision. The points are computed in double precision, in which they are exact for any sample the package can hold (up to 2^53 points). With single-precision (Float32) data they are rounded to single precision; a point that would round to 1 is set to 1 − 2^−24, the largest single-precision number below 1, because the MCI change of variables is infinite at 1.

Storage. The draws are generated once per fit, as one N × D matrix in the data’s element type (8 bytes per draw in Float64, 4 in Float32; on the GPU for GPU fits). The likelihood, its derivatives, the efficiency indices and predict() read this matrix a group of rows at a time without copying it (see About GPU and chunks options), and the result keeps it, so predict() uses exactly the fit’s draws. A result holds the matrix as long as it is in use: 164 MB for N = 5,000 at the default D in Float64.

Example. With N = 200 observations and D = 64 draws the package generates Q = 12,800 points; observation 1 receives points 1 to 64 and observation 200 points 12,737 to 12,800.

Recycling (option). recycling = true caps the sequence at L = 2^24 − 1 = 16,777,215 points, and recycling = L with an integer L, D ≤ L ≤ 2^24 − 1, at L points. The package then generates min(Q, L) points and, when Q exceeds L, restarts from the first point: observation i receives the points at positions mod1((i − 1)D + j, L), j = 1, …, D. When the cap L = 2^24 − 1 binds (Q ≥ L), the pool is exactly {j/2^24 : j = 1, …, 2^24 − 1}. When N > L/g, where g is the greatest common divisor of D and L (g = 1 included), observations i and i + L/g receive identical draws, and the package prints a warning that names the remedies; L = 2^24 − 1 is odd, so with recycling = true a power-of-two D gives g = 1. Recycling applies only to the draws the package generates for each observation (multiRand = true, no draws). This capped recycling is the scheme of Chen and Wang (2026).

Draws of versions before 2.0.0. Versions before 2.0.0 recycled a sequence of 2^m − 1 points, the longest such length not above N × D or distinct_Halton_length (32,767 by default), and their default n_draws was 1,024. To reproduce the draws of a fit of those versions that used the default length, give recycling = 2^15 - 1 and that fit’s n_draws (1,024 if it used the default): the draws are identical whenever N × D is at least 32,767. The keyword distinct_Halton_length is deprecated: earlier :MCI and :MSLE scripts that set it still run, with a warning, and with the same n_draws get the draws they got before 2.0.0. Giving both recycling and distinct_Halton_length is an error.

# Default: each observation receives its own 4,096 points; no point is used twice
meth = sfmodel_method(method = :MSLE)

# More draws per observation; no other setting is needed
meth = sfmodel_method(method = :MSLE, n_draws = 2^15)

# Recycling with the cap 2^24 - 1
meth = sfmodel_method(method = :MSLE, recycling = true)

# The draws of a fit of a version before 2.0.0 that used the defaults (identical for N ≥ 32)
meth = sfmodel_method(method = :MSLE, n_draws = 1024, recycling = 2^15 - 1)

# Shared draws: every observation uses the same first 4,096 points
meth = sfmodel_method(method = :MSLE, multiRand = false)

Custom Draw Sequences

Instead of using the built-in base-2 Halton sequence, users can supply their own uniform draws \(\{r^d\}\), \(d = 1, \ldots, D\), via the draws option in sfmodel_method(). This allows the use of alternative low-discrepancy sequences (e.g., Halton with a different base, Sobol sequences) or pseudo-random numbers.

Supplying draws means the package’s generator is not used, so multiRand no longer has a mode to choose: it is set to false automatically, and the shape of what you supply decides how the draws are read.

What you supply How it is read
a length-\(D\) vector, a \(1 \times D\) row matrix, or a \(D \times 1\) column matrix one sequence of \(D\) draws, shared by every observation
an \(N \times D\) matrix (\(N\) = number of observations; for panel models, number of firms) one row of \(D\) draws per observation
any other row count error — the block cannot be split at the observation level

A single-column matrix is always read as a shared sequence, even when it happens to have \(N\) rows: the column count is tested first, so rand(N, 1) is \(N\) shared draws, not one draw per observation.

Draw values must lie in \([0, 1)\). A draw of exactly \(1\) is rejected: the MCI change of variables has an infinite Jacobian there, and the MSLE and panel quantile kernels would silently move the draw to their upper clamp instead, so all three backends refuse it rather than estimate a different model; a draw of \(0\) is accepted, being the lower bound of the support. The check is applied again after the draws are converted to the data’s element type, since a Float64 value just below one becomes exactly 1.0f0 in a Float32 model.

The n_draws option is ignored when draws is supplied: D is taken from what you give. The result records multiRand = false, n_draws = D and user_draws_supplied = true and keeps the draws (result.model): predict() uses them when its draws argument is omitted, and a draws argument, in any of the equivalent shapes above, replaces them. When the supplied array already has the element type of the data and lives on the fit’s device, the fit uses it without a copy and the result refers to it, so changing the array after the fit changes what predict() computes. predict() reads the element-type rule the same way sfmodel_method() does, so an integer or rational container is refused at both ends rather than at one; and if the fit ran on the GPU and was given a CuArray, that same object is accepted by predict(), which copies it to the host before running its CPU path.

# Example 1: one custom sequence shared by every observation.
# `make_halton_p` is internal, so it must be qualified; any length-D vector of values in [0, 1) works.
halton_vec = SFrontiers.MCI_Backend.make_halton_p(1024; T = Float64)

meth = sfmodel_method(method = :MSLE, draws = halton_vec)   # 1×1024 or 1024×1 would be read identically

# Example 2: pseudo-random uniform draws, shared by every observation
D = 1024
meth = sfmodel_method(method = :MSLE, draws = rand(D))

# Example 3: observation-specific custom draws (N × D)
N = 500
my_block = rand(N, D)                                       # row i is observation i's sequence

meth = sfmodel_method(method = :MSLE, draws = my_block)

Handling Convergence Issues

If estimation fails to converge:

  1. Try different initial values

    Convergence failures are often caused by poor starting points. Use sfmodel_init() to supply values closer to the expected estimates — for example, based on OLS residuals or results from a simpler model. Even small changes in initial values can determine whether the optimizer finds the global maximum or gets stuck at a local optimum or saddle point. Starting values must lie inside the parameter bounds (Parameter Bounds): under :MCI and :MSLE, and under :MLE for panel_TFE_CSW and panel_TRE, a start at or beyond the bound of a homoscedastic parameter is refused, and one that puts a heteroscedastic parameter at or beyond its bound at some observations gives a warning.

  2. Change warmstart iterations

    Note, more warmstart iterations are not always better — an excessive warmstart can overshoot and move the parameters away from the basin of the global optimum, making it harder for the main solver to converge.

    myopt = sfmodel_opt(
    warmstart_solver = NelderMead(),
    warmstart_opt = (iterations = 400,),  # More warmstart iterations
    main_solver = Newton(),
    main_opt = (iterations = 200,)
)

  3. Use different optimizers

    myopt = sfmodel_opt(
    warmstart_solver = ParticleSwarm(),  # Global search, slow
    warmstart_opt = (iterations = 500,),
    main_solver = BFGS(),  # Alternative to Newton
    main_opt = (iterations = 2000,)
)

  4. Try a different estimation method

    If one method has convergence difficulties, try another:

    # If MSLE fails, try MCI (or vice versa)
meth_alt = sfmodel_method(method = :MCI)
result = sfmodel_fit(spec = spec, method = meth_alt)

# Or try MLE (if the model supports it: Normal noise, no copula,
# half-normal/truncated-normal/Exponential inefficiency)
meth_mle = sfmodel_method(method = :MLE)
result = sfmodel_fit(spec = spec, method = meth_mle)

  5. Check OLS residual skewness

    Before investing effort in convergence tuning, check whether the OLS residuals are skewed in the direction inefficiency implies (sf_skewness_test(result) gives the one-sided test). If result.OLS_resid_skew has the wrong sign (positive for production, negative for cost), the data may not exhibit the one-sided pattern that stochastic frontier models require. In such cases, even a perfectly converged model may produce meaningless estimates.

  6. Reduce model complexity first

    If a heteroscedastic or copula model fails to converge, first estimate a simpler version:

    • Drop the copula (copula = :None) to establish a baseline.
    • Remove heteroscedasticity (hetero = Symbol[]) and use a homoscedastic specification.
    • Use a simpler inefficiency distribution (e.g., half-normal instead of Lognormal).

    Once the simple model converges, use its estimates as initial values for the more complex specification.

  7. Rescale variables measured in very large or very small units

    redflag = 1 with every standard error NaN can come from a Hessian whose reciprocal condition number is below machine epsilon (see Convergence Warnings). Besides collinearity, a common cause is variables on wildly different scales, for example one regressor in units a million times larger than another. Rescale such variables (for example to thousands or millions) and refit; the estimates change only by the scale factor.

  8. Laplace noise: let the BFGS finish work, or start with BFGS.

    At the kinked maximum of the simulated Laplace likelihood Newton’s method usually cannot meet the gradient tolerance; SFrontiers continues such fits with BFGS automatically (see Supported Models); with the default optimizer settings, whether omitted or written out, it stops Newton after 30 iterations for this reason. main_solver = BFGS() skips the Newton stage, whose iterations each compute a Hessian, and is usually faster for these models.

10. Panel Data Models

The module supports several panel stochastic frontier models for estimating firm-level inefficiency from balanced or unbalanced panel data. Panel estimation is accessed through the same unified API by setting the datatype argument in sfmodel_spec().

Panel Model Types

datatype Model Methods Ineff (MLE)
:panel_TFE Wang and Ho (2010) true fixed-effect MCI, MSLE, MLE half-normal, truncated-normal
:panel_TFE_CSW Chen, Schmidt, and Wang (2014) fixed-effect MLE only half-normal only
:panel_TRE Greene (2005) True random-effect MLE only half-normal, truncated-normal

For panel_TFE, the simulation-based methods (MCI, MSLE) support all 11 inefficiency distributions (Gamma is MCI only, exactly as in the cross-sectional case). MLE support is limited to the distributions listed above. For panel_TFE_CSW and panel_TRE, only MLE is available.

10.1 Theoretical Background

Wang and Ho (2010) True Fixed-Effect (panel_TFE)

The Wang and Ho (2010) model starts from:

\[ y_{it} = \alpha_i + x_{it}'\beta + v_{it} - h(z_{it}) \cdot u_i^* \]

where \(\alpha_i\) is a firm-specific fixed effect, \(v_{it} \sim N(0, \sigma_v^2)\) is noise, \(u_i^* \ge 0\) is inefficiency, and \(h(z_{it}) = \exp(z_{it}'\delta)\) is a scaling function.

To eliminate \(\alpha_i\), a within-group transformation (demeaning) is applied:

\[ \tilde{y}_{it} = \tilde{x}_{it}'\beta + \tilde{v}_{it} - \tilde{h}_{it} \cdot u_i^* \]

where tildes denote demeaned values. Key point: \(y\) and \(X\) are demeaned, but \(Z\) is NOT demeaned. Instead, \(h(z_{it})\) is computed first, then demeaned to obtain \(\tilde{h}_{it}\).

Because the demeaned noise has a singular covariance \(\Sigma = \sigma_v^2(I - \frac{1}{T}\mathbf{1}\mathbf{1}')\), the quadratic form simplifies to:

\[ \text{pert}' \Sigma^+ \text{pert} = \|\text{pert}\|^2 / \sigma_v^2 \]

This eliminates the need for the pseudo-inverse, keeping computation efficient.

Chen, Schmidt, and Wang (2014) Fixed-Effect (panel_TFE_CSW)

The CSW model (Chen, Schmidt, and Wang 2014, Journal of Econometrics) provides an alternative approach to estimating true fixed-effect stochastic frontier models. After the within-group transformation eliminates the fixed effects \(\alpha_i\), the CSW approach exploits properties of the closed skew-normal (CSN) distribution to derive the likelihood of the demeaned composed error in terms of a multivariate-normal orthant probability, which is evaluated for each firm by one-dimensional numerical quadrature, without simulation. This avoids the need for the scaling-property structure required by Wang and Ho (2010).

Key characteristics:

  • No scaling function needed. Unlike the Wang-Ho TFE model, CSW does not require the \(h(z_{it}) = \exp(z_{it}'\delta)\) structure. Consequently, no zvar argument is needed.
  • No exogenous inefficiency determinants. Because there is no scaling function, this model cannot incorporate Z variables that explain heterogeneity in inefficiency.
  • MLE only. The likelihood needs no simulation (its orthant probability is a one-dimensional integral, evaluated by quadrature for each firm), and only the MLE method is available.
  • Half-normal inefficiency only. The CSN derivation relies on the half-normal distribution.
  • Long panels. Each firm’s likelihood contains two quantities that shrink or grow geometrically with \(T_i\): the determinant \((\sigma_u^2+\sigma_v^2)^{T_i-1}/T_i\) of the covariance matrix of the demeaned errors, and a one-dimensional integral over a product of \(T_i\) normal CDFs (an orthant probability, evaluated by numerical quadrature), which tends to \(2^{-T_i}\) as \(\sigma_u/\sigma_v \to 0\). Their logarithms are computed in log space where the direct form would fail (the probability at or below \(10^{-15}\), the determinant outside \([10^{-154}, 10^{154}]\)), so the panel length does not limit the accuracy of the likelihood; and once \(\sigma_u/\sigma_v\) exceeds 300, the probability is computed in log space for every firm, because there the direct quadrature can miss (by up to about 0.2 nats per firm). Below 300 the direct quadrature is kept. It is accurate except for a firm whose probability lies in one of two narrow windows, from \(10^{-15}\) to about \(5 \times 10^{-15}\) and from about \(7 \times 10^{-5}\) to \(10^{-4}\): there it can miss by up to about 0.07 nats per firm near \(\sigma_u/\sigma_v = 300\), \(7 \times 10^{-3}\) at 200 and \(2 \times 10^{-5}\) at 100 for a firm with two or three periods, and by much less for a firm with more periods (near 300, \(5 \times 10^{-3}\) with five periods and \(1.5 \times 10^{-5}\) with twenty). In 168 fits of panels built with one firm in such a window, these misses did not affect the converged estimates, but an optimizer can pass through such points on its way. In versions before 2.0.0 the probability was floored at \(10^{-15}\), which made the log-likelihood too high on panels longer than about 45 periods (and on shorter panels at parameters far from the optimum), and the determinant was formed directly, which made the log-likelihood infinite, or its Hessian unusable, on long panels with \(\sigma_u^2+\sigma_v^2\) far from 1. The log-space computation also keeps the gradient and the Hessian of the likelihood accurate up to the bound on \(\sigma_v^2\) described next, as long as \(\sigma_u/\sigma_v\) stays below about \(10^{10}\) (further out, the peak of the integrand becomes too narrow to place in double precision, and the direct quadrature’s value is kept, with derivatives that are not accurate); without that accuracy near the bound of \(\sigma_v^2\), most fits that run toward \(\sigma_v \to 0\) would end without converging. Inside the likelihood, \(\sigma_u^2\) and \(\sigma_v^2\) are held within \([10^{-12}, 10^{12}]\) (as in this model’s jlms and bc and in the panel_TRE likelihood), so an optimizer step that drives \(\sigma_v^2\) to zero does not stop the estimation with an error; beyond those bounds the likelihood is flat in that variance, and a fit that ends there is reported as a boundary solution, with redflag = 1, a singular Hessian and NaN standard errors, and with the coefficient of that variance reported at the bound (see Parameter Bounds). Such a fit need not be at the highest likelihood the data allow: a refit started from its end point with a larger \(\sigma_v^2\) can find an interior maximum with a higher log-likelihood. When a fit reports this bound, refit it from other starting values (init) with the variance inside its bounds (a start at or beyond a bound is refused), and compare the log-likelihoods.

True Random-Effect (panel_TRE)

The TRE model, attributed to Greene (2005), treats the individual effect \(\alpha_i\) as a random draw from \(N(0, \sigma_\alpha^2)\) rather than as a fixed parameter to be eliminated. Because \(\alpha_i\) is random and integrated out of the likelihood, a constant term may be included in the frontier equation (unlike the fixed-effect models where demeaning eliminates constants).

Key characteristics:

  • Random individual effects. Assumes \(\alpha_i\) is uncorrelated with the regressors \(x_{it}\). If this assumption is violated (e.g., firm size is correlated with both input choices and the firm effect), the TRE estimates may be inconsistent.
  • MLE only. Available with half-normal or truncated-normal inefficiency.
  • Constant term allowed. Unlike TFE and CSW, you may include a column of ones in frontier.
  • No zvar. The TRE likelihood has no inefficiency-determinant equation: the truncated-normal inefficiency mean \(\mu\) is a scalar constant (the half-normal form has none), and the inefficiency variance is constant. sfmodel_spec() therefore refuses a zvar argument for panel_TRE rather than silently ignoring it (see the zvar row of the sfmodel_spec() argument table in Section 6.1). For a panel model with inefficiency determinants, use panel_TFE, whose scaling function \(h(z_{it}) = \exp(z_{it}'\delta)\) is exactly that.

When to use TRE vs. TFE:

The choice between TRE and TFE mirrors the classic random-effects vs. fixed-effects tradeoff in panel econometrics:

  • Use TRE when firm-specific effects are believed to be uncorrelated with the regressors. TRE is more efficient (uses both within- and between-variation) but inconsistent if the uncorrelatedness assumption fails.
  • Use TFE (Wang-Ho or CSW) when correlation between firm effects and regressors is likely. TFE is consistent regardless of this correlation but less efficient.

10.2 Panel Quick Start

Example: Panel TFE with MSLE (simulation-based)

using CUDA
using SFrontiers
using CSV, DataFrames, Optim
using Statistics          # `mean` comes from Statistics, not from SFrontiers

# Load panel data (stacked: firm 1 all T periods, firm 2 all T periods, ...)
df = CSV.read("panel_data.csv", DataFrame)
y = df.y
X = hcat(df.x1, df.x2)    # NT x K — no constant column!
Z = hcat(df.z1)            # NT x L — no constant column!

# Step 1: Specify panel model
myspec = sfmodel_spec(
    type = :production,
    datatype = :panel_TFE,    # Wang and Ho 2010 true fixed-effect
    depvar = y,
    frontier = X,
    zvar = Z,
    noise = :Normal,
    ineff = :HalfNormal,
    id = df.firm,             # unit identifier (required for all panel models)
)

# Step 2: Choose estimation method
mymeth = sfmodel_method(method = :MSLE)    # 4,096 draws per firm by default

# Step 3: Set initial values (panel-specific keywords)
myinit = sfmodel_init(
    spec = myspec,
    scaling = [0.1],          # scaling function coefficient
    ln_sigma_u_sq = 0.1,       # scalar
    ln_sigma_v_sq = 0.1      # scalar
)

# Step 4: Configure optimization
myopt = sfmodel_opt(
    warmstart_solver = NelderMead(),
    warmstart_opt = (iterations = 200, g_abstol = 1e-3),
    main_solver = Newton(),
    main_opt = (iterations = 200, g_abstol = 1e-8)
)

# Step 5: Estimate
result = sfmodel_fit(
    spec = myspec,
    method = mymeth,
    init = myinit,
    optim_options = myopt,
    show_table = true
)

# Access results
println("Log-likelihood: ", result.loglikelihood)
println("Mean JLMS: ", mean(result.jlms))      # observation-level, NT-vector
println("Mean BC: ", mean(result.bc))            # observation-level, NT-vector

Example: Panel TFE with MLE (analytic)

# Same spec as above — MLE is available when ineff is half-normal or truncated-normal
mymeth_mle = sfmodel_method(method = :MLE)  # no draws needed
result_mle = sfmodel_fit(spec = myspec, method = mymeth_mle, show_table = true)

Example: Panel TFE_CSW (MLE only)

spec_csw = sfmodel_spec(
    datatype = :panel_TFE_CSW,
    depvar = y,
    frontier = X,
    noise = :Normal,
    ineff = :HalfNormal,        # CSW requires half-normal
    id = firm_id
)
meth = sfmodel_method(method = :MLE)
result = sfmodel_fit(spec = spec_csw, method = meth)

Example: Panel TRE (MLE only)

spec_tre = sfmodel_spec(
    datatype = :panel_TRE,
    depvar = y,
    frontier = X,               # a constant column IS allowed here
    noise = :Normal,
    ineff = :HalfNormal,        # or :TruncatedNormal
    id = firm_id
)
meth = sfmodel_method(method = :MLE)
result = sfmodel_fit(spec = spec_tre, method = meth)

Neither :panel_TFE_CSW nor :panel_TRE has an inefficiency-determinant equation, so neither accepts zvar; passing it raises an error that says so. Use :panel_TFE, whose scaling function \(h(z)=\exp(z'\delta)\) is exactly that, if you need determinants in a panel.

Starting values for the two MLE-only panel models

Both take the same sfmodel_init() as everything else, and every component is optional. :panel_TRE additionally has sigma_a_sq, the random-effect variance, which no other model has.

# panel_TFE_CSW: [frontier, ln_sigma_u_sq, ln_sigma_v_sq]
init_csw = sfmodel_init(spec = spec_csw,
                        frontier = X \ y,
                        ln_sigma_u_sq = log(0.25),
                        ln_sigma_v_sq = log(0.09))

# panel_TRE, half-normal: [frontier, sigma_a_sq, ln_sigma_u_sq, ln_sigma_v_sq].
# With ineff = :TruncatedNormal, mu comes between the frontier block and sigma_a_sq.
init_tre = sfmodel_init(spec = spec_tre,
                        frontier = X \ y,
                        sigma_a_sq = log(0.16),
                        ln_sigma_u_sq = log(0.25),
                        ln_sigma_v_sq = log(0.09))

result = sfmodel_fit(spec = spec_tre, method = meth, init = init_tre)

10.4 No Constant Columns

In the Wang and Ho (2010) panel model (panel_TFE), within-group demeaning eliminates any constant terms. Therefore:

  • Do NOT include a column of ones in frontier or zvar.
  • The model will raise an error if a constant column is detected.
  • This differs from cross-sectional models, where constants are typically required.
  • The same applies to panel_TFE_CSW, though there the check fires at sfmodel_fit() rather than at sfmodel_spec(). For panel_TRE, a constant term is allowed in frontier (see Section 10.1).
